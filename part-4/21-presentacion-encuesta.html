21  Presentación y experiencia de participación

21.1 Objetivos

Al terminar este capítulo vas a poder

  1. agregar una barra de progreso y explicar qué información da;

  2. explicar qué es CSS y para qué sirve una hoja de estilos;

  3. sumar el archivo styles.css al proyecto;

  4. adaptar el estudio a pantallas de celular y comprobarlo desde la computadora;

  5. revisar la legibilidad y la accesibilidad de las pantallas;

  6. distinguir un cambio de apariencia de un cambio en el instrumento.

21.2 Para empezar, una pantalla que funciona pero se ve mal

Tu estudio funciona. Tiene consentimiento, cuestionario, escalas en orden aleatorio, reglas condicionales y un control de atención. Pero todavía no pensaste cómo se ve.

Abrí el estudio desde un celular, o imaginalo. El texto aparece chiquito, porque el navegador muestra la página como si fuera una pantalla de computadora achicada. Las cinco opciones de las escalas quedan apretadas en una línea, y la persona no sabe cuántas pantallas le faltan. Y mucha gente va a responder tu encuesta desde el celular.

Google Forms resuelve esto por su cuenta. Adapta el formulario al celular, muestra una barra de progreso si la activás y usa un diseño uniforme. En jsPsych, la apariencia también es una decisión que queda escrita en un archivo.

Idea clave

La presentación cambia cómo se ve el estudio, no qué se pregunta. Aun así, algunas decisiones de presentación pueden influir en las respuestas, y por eso también se especifican, se verifican y se documentan.

21.3 La barra de progreso

jsPsych puede mostrar una barra de progreso arriba de cada pantalla, que avanza a medida que la persona completa pantallas. Se activa en la configuración general de jsPsych.

const jsPsych = initJsPsych({
  show_progress_bar: true,
  message_progress_bar: "Progreso",
  on_finish: function () {
    jsPsych.data.get().localSave("csv", "datos_" + participante + ".csv");
  }
});

show_progress_bar: true activa la barra y message_progress_bar define el texto que aparece al lado. Si no lo ponés, jsPsych muestra el texto en inglés “Completion Progress”.

La barra avanza según la cantidad de pantallas de la línea de tiempo. Con reglas condicionales ese cálculo es aproximado, porque si la pregunta sobre herramientas de IA no aparece, la barra no lo sabe de antemano. En tu estudio la diferencia es chica.

Mostrar el progreso es una decisión que puede tener efectos sobre la participación. Puede motivar a terminar cuando falta poco o desanimar cuando falta mucho, y la investigación sobre este efecto tiene resultados mixtos. En una encuesta corta como la tuya, la barra suele ser útil. En un estudio largo, conviene pensarlo.

21.4 CSS

En el capítulo de tu primer estudio viste que index.html carga una hoja de estilos de jsPsych. Una hoja de estilos es un archivo escrito en CSS, un lenguaje que describe la apariencia de una página, como tamaños, colores, márgenes y la disposición de los elementos. Estos archivos tienen la extensión .css.

Tu proyecto va a tener su propia hoja de estilos, styles.css, y con eso la estructura llega a una etapa nueva.

mi-primer-estudio/
├── index.html
├── experiment.js
├── styles.css
├── diccionario.md
└── README.md

Ahora cada archivo tiene una función clara. index.html dice qué cargar, experiment.js define el procedimiento, styles.css define la apariencia, diccionario.md documenta los datos y README.md presenta el proyecto.

21.4.1 Selector y declaraciones

Una regla de CSS dice a qué elementos se aplica y qué apariencia tienen que tener.

body {
  font-size: 18px;
  line-height: 1.5;
}

La primera parte, body, es el selector, que indica a qué elementos se aplica la regla. body es el cuerpo de la página, o sea, todo su contenido. Entre llaves van las declaraciones. Cada una tiene una propiedad y un valor, unidos por dos puntos y terminados en punto y coma. font-size: 18px pone el tamaño del texto en 18 píxeles y line-height: 1.5 pone el espacio entre líneas en una vez y media el tamaño del texto.

Para este curso no hace falta aprender CSS. Lo que hace falta es poder leer una regla, reconocer qué cambia y comprobar su efecto.

21.5 La hoja de estilos del estudio

El archivo styles.css de tu estudio tiene tres partes.

/* Apariencia del estudio. Estos estilos cambian cómo se ve el estudio, no su procedimiento. */

/* Texto más grande y con más espacio entre líneas, para facilitar la lectura */
body {
  font-size: 18px;
  line-height: 1.5;
}

/* Ancho máximo del contenido, para que las líneas no sean demasiado largas en pantallas grandes */
.jspsych-content {
  max-width: 700px;
}

/* En pantallas angostas, como las de un celular, las opciones de las escalas se muestran una debajo de la otra */
@media (max-width: 600px) {
  .jspsych-content {
    padding: 0 16px;
  }
  #jspsych-survey-likert-form .jspsych-survey-likert-opts li {
    display: block;
    width: 100% !important;
    text-align: left;
    margin-bottom: 8px;
  }
  #jspsych-survey-likert-form .jspsych-survey-likert-opts li input[type=radio] {
    display: inline-block;
    position: static;
    margin: 0 8px 0 0;
  }
  #jspsych-survey-likert-form .jspsych-survey-likert-opts:before {
    display: none;
  }
}

  1. Lo que está entre /* y */ son comentarios de CSS, y cumplen la misma función que // en JavaScript.

  2. La regla de body agranda el texto y el espacio entre líneas.

  3. La regla de .jspsych-content limita el ancho del contenido, porque las líneas muy largas se leen mal en pantallas grandes. El punto del principio indica que el selector se refiere a una clase, que es un nombre que jsPsych les pone a ciertos elementos.

  4. El bloque @media (max-width: 600px) tiene reglas que solo se aplican cuando la pantalla mide 600 píxeles de ancho o menos, como la de un celular. Esas reglas agregan un margen a los costados y muestran las opciones de las escalas una debajo de la otra, en vez de una al lado de la otra.

Los selectores del bloque para celulares son largos porque el plugin survey-likert agrega sus propios estilos al mostrar la escala. Para que los estilos del estudio tengan prioridad, los selectores tienen que ser más específicos, y !important cumple esa misma función en un caso puntual. No hace falta que memorices estos detalles. Si algún día un estilo no se aplica, podés pedirle al agente que te explique por qué.

21.6 Una línea para el celular

Los navegadores de los celulares suelen mostrar las páginas como si fueran pantallas de computadora achicadas. Para que usen el ancho real del dispositivo, index.html necesita esta línea dentro de <head>.

<meta name="viewport" content="width=device-width, initial-scale=1">

Sin ella, las reglas para pantallas angostas no se aplicarían en el celular, porque el navegador creería que la pantalla es ancha.

Además, index.html tiene que cargar styles.css después de la hoja de estilos de jsPsych. Cuando dos reglas con la misma especificidad se contradicen, gana la que se carga después.

<link rel="stylesheet" href="https://unpkg.com/jspsych@8.3.0/css/jspsych.css">
<link rel="stylesheet" href="styles.css">

21.7 Cuando la presentación cambia el instrumento

Casi todos los cambios de este capítulo solo afectan la comodidad, como el tamaño del texto, los márgenes o la barra de progreso. Pero otros pueden influir en cómo se responde.

Mostrar las opciones de una escala en vertical y no en horizontal es un ejemplo. En horizontal, las opciones forman un continuo visual de izquierda a derecha, y en vertical forman una lista. La investigación sobre encuestas muestra que la disposición visual de las opciones puede afectar las respuestas en algunos casos.

Tu estudio usa disposición horizontal en computadoras y vertical en celulares. Es una decisión razonable para que se lea mejor, pero introduce una diferencia entre dispositivos. Por eso conviene documentarla y, en el análisis, poder saber qué dispositivo usó cada persona. Con una escala validada, conviene además revisar si sus autores indican una forma de presentación.

La accesibilidad también es una decisión de diseño

Una encuesta accesible la puede responder más gente, incluidas personas con dificultades visuales o motoras. Algunas prácticas básicas son usar un texto de tamaño suficiente, mantener buen contraste entre el texto y el fondo, no transmitir información solo con colores y permitir hacer clic sobre el texto de cada opción y no solo sobre el círculo. Los plugins de encuesta de jsPsych ya cumplen esta última condición.

21.8 Por qué nos importa en Psicología

La experiencia de participación afecta la calidad de los datos. Un texto difícil de leer aumenta los errores, una escala incómoda en el celular aumenta el abandono y una pantalla confusa aumenta las respuestas descuidadas que vimos en el capítulo sobre controles de atención.

Además, la presentación forma parte del procedimiento que se informa. Si dos grupos de personas vieron la escala de maneras distintas, esa diferencia se tiene que conocer y documentar.

21.11 Verificar en computadora y en celular

Los navegadores permiten simular la pantalla de un celular desde la computadora, con las herramientas para desarrolladores que ya usaste para ver la consola.

Actividad guiada

En la computadora.

  1. Recargá el estudio con F5 y comprobá que aparezca la barra de progreso con el texto “Progreso”.

  2. Avanzá algunas pantallas y comprobá que la barra avance.

  3. Comprobá que el texto se vea más grande que antes y que las escalas muestren las opciones en horizontal.

En la simulación de celular.

  1. Apretá F12 para abrir las herramientas para desarrolladores.

  2. Apretá Ctrl + Shift + M, o buscá arriba de las herramientas el ícono con forma de celular y tableta. La página se va a mostrar con el tamaño de un celular.

  3. Recargá la página y avanzá hasta una escala. Comprobá que las opciones aparezcan una debajo de la otra y que el texto no quede pegado a los bordes.

  4. Probá responder haciendo clic sobre el texto de las opciones.

En los datos.

  1. Completá el estudio en la simulación de celular y abrí el archivo de datos.

  2. Comprobá que tenga las mismas columnas y la misma cantidad de filas que antes de agregar los estilos.

El último paso verifica que el cambio fue solo de apariencia. Si los datos cambiaron, se modificó algo más que la presentación.

La simulación es una aproximación. Cuando publiques el estudio, en la Parte V, lo vas a poder probar en un celular de verdad.

21.12 Actualizar la documentación

Actividad guiada

  1. En README.md, sumá styles.css a la descripción de los archivos del proyecto.

  2. En diccionario.md o en el README, agregá una nota que diga que las escalas se muestran en horizontal en pantallas anchas y en vertical en pantallas de hasta 600 píxeles.

  3. Agregá una entrada al registro de cambios.

21.13 Errores frecuentes

21.13.1 Los estilos no se aplican

Fijate que index.html cargue styles.css y que el nombre del archivo coincida exactamente. Fijate también que esa línea esté después de la que carga la hoja de estilos de jsPsych, y recargá la página con F5.

21.13.2 En el celular todo se ve chiquito

Falta la línea <meta name="viewport" ...> en index.html, o está fuera de <head>.

21.13.3 La barra de progreso aparece en inglés

Falta message_progress_bar en la configuración de jsPsych.

21.13.4 Un cambio de estilo hizo desaparecer una pantalla

Un error de sintaxis en CSS no suele romper el estudio, pero puede esconder elementos. Revisá la última regla que cambiaste y compará con la copia de respaldo.

21.13.5 Los estilos cambiaron el procedimiento

Si después de este capítulo cambió el orden, el contenido o los datos, el cambio no fue solo de apariencia. Compará experiment.js con la copia de respaldo.

21.15 En síntesis

La presentación del estudio es una decisión de diseño. La barra de progreso dice cuánto falta y puede influir en la participación, y en jsPsych se activa en la configuración general.

CSS describe la apariencia de una página. Con una hoja de estilos propia, styles.css, cambiamos tamaños, márgenes y disposición sin tocar el procedimiento. Un bloque @media aplica reglas solo en pantallas angostas, y la línea viewport de index.html hace que los celulares usen su ancho real.

Algunos cambios de presentación, como la disposición de las opciones de una escala, pueden influir en las respuestas y hay que documentarlos. La accesibilidad también es parte del diseño.

Un cambio de apariencia se verifica en la computadora, en la simulación de celular y en los datos, que no tienen que cambiar.

21.16 Desafío

  1. Cambiá en styles.css el tamaño del texto de 18 a 20 píxeles. Mirá el efecto en la computadora y en la simulación de celular, y después volvé a 18.

  2. Proponé una regla nueva que cambie el color del texto de las instrucciones. Antes de aplicarla, pensá si el color que elegiste mantiene buen contraste con el fondo blanco.

  3. Imaginá que una escala validada dice en sus instrucciones que las opciones tienen que ir en horizontal. Explicá qué harías con la regla para celulares y qué alternativas tendrías.

  4. Explicá qué información tendrías que registrar en los datos para saber si cada persona respondió desde una pantalla angosta o ancha. No la implementes, describí la variable como si fuera una fila del diccionario.
