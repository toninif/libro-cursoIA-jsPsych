18  Lógica condicional

18.1 Qué vas a poder hacer

Al terminar este capítulo, vas a poder realizar las siguientes acciones.

  1. Vas a poder expresar una regla del procedimiento con la forma “si ocurre…, entonces…”.

  2. Vas a poder dibujar las ramas posibles de un estudio.

  3. Vas a poder terminar el estudio cuando una persona no acepta el consentimiento o no cumple un criterio de inclusión.

  4. Vas a poder mostrar una pregunta de seguimiento solo cuando corresponde.

  5. Vas a poder distinguir un dato faltante de una pregunta que no aplica.

  6. Vas a poder diseñar casos de prueba que recorran cada rama.

18.2 Un solo camino permite formular el problema

Hasta ahora tu estudio tiene un único recorrido. Todas las personas ven las mismas pantallas en la misma secuencia, salvo el orden aleatorio de las escalas. Esa estructura genera tres problemas.

Primero, el consentimiento tiene un solo botón. Quien no quiere participar tiene que cerrar la ventana. No hay una forma explícita de decir que no, y el estudio no confirma que la decisión fue respetada.

Segundo, el estudio está pensado para estudiantes universitarios, pero no lo comprueba. Cualquier persona que reciba el enlace puede responder.

Tercero, algunas preguntas solo tienen sentido para algunas personas. Si alguien eligió “Herramientas de IA” entre sus recursos de estudio, podría interesarte saber cuáles usa. Preguntárselo a quien no las usa sería confuso.

Google Forms resuelve algunas de estas situaciones con la opción “Ir a la sección según la respuesta”. jsPsych las resuelve con lógica condicional: reglas que deciden qué ocurre a continuación según lo que pasó antes.

Idea clave

Una regla condicional tiene la forma “si ocurre…, entonces…”. Cada regla crea ramas en el procedimiento. Cada rama produce un archivo de datos diferente y necesita su propia verificación.

18.3 Una regla condicional tiene una condición y una consecuencia

Antes de escribir código, conviene formular cada regla en palabras. Tu estudio va a tener tres reglas.

  1. Si la persona elige “No acepto” en el consentimiento, entonces el estudio termina con un mensaje.

  2. Si la persona responde que no estudia en la universidad, entonces el estudio termina con otro mensaje.

  3. Si la persona eligió “Herramientas de IA” entre sus recursos, entonces aparece una pregunta sobre qué herramientas usa.

Cada regla tiene dos partes. La condición es lo que se comprueba: una respuesta anterior. La consecuencia es lo que ocurre si la condición se cumple: terminar el estudio o mostrar una pantalla.

Cada condición depende de un dato previo. Identificar ese dato es el primer paso para implementar la regla y para verificarla después.

18.4 Las ramas se pueden dibujar

Cuando un procedimiento tiene reglas condicionales, conviene dibujar sus ramas. El dibujo permite ver todos los recorridos posibles antes de implementarlos.

El diagrama muestra cuatro recorridos: dos terminan antes, uno completa el estudio sin la pregunta de seguimiento y uno la incluye. Vas a tener que probar los cuatro.

18.5 Terminar el estudio es una consecuencia

Para terminar el estudio cuando la persona no acepta, el consentimiento necesita dos botones y una regla. jsPsych permite ejecutar instrucciones cuando un ensayo termina, mediante el parámetro on_finish. Ya lo usaste en la configuración general de jsPsych para guardar los datos al final del estudio. Ahora lo vas a usar en un ensayo.

const consentimiento = {
  type: jsPsychHtmlButtonResponse,
  stimulus:
    "<h2>Consentimiento informado</h2>" +
    "<p>Este estudio forma parte de una actividad de aprendizaje. Vas a responder preguntas sobre tus datos generales y tus hábitos de estudio.</p>" +
    "<p>La participación dura aproximadamente 5 minutos. Es voluntaria y anónima. Podés abandonar el estudio en cualquier momento cerrando esta ventana.</p>" +
    "<p>Indicá si aceptás participar.</p>",
  choices: ["Acepto participar", "No acepto"],
  data: { pantalla: "consentimiento" },
  on_finish: function (data) {
    // Si la persona elige "No acepto" (el segundo botón, posición 1), el estudio termina.
    if (data.response === 1) {
      jsPsych.abortExperiment("<p>Elegiste no participar. El estudio terminó y no se registraron respuestas a las preguntas. Podés cerrar esta ventana.</p>");
    }
  }
};

Las partes nuevas son estas.

  1. choices tiene dos botones. Como viste en el capítulo sobre los datos, jsPsych registra la posición del botón presionado: 0 para “Acepto participar” y 1 para “No acepto”.

  2. on_finish: function (data) { ... } contiene instrucciones que se ejecutan cuando el ensayo termina. La palabra data da acceso a los datos de ese ensayo.

  3. if (data.response === 1) { ... } es la regla. if significa “si”. Lo que está entre paréntesis es la condición: que la respuesta sea igual a 1. El signo === compara si dos valores son iguales. Lo que está entre llaves es la consecuencia.

  4. jsPsych.abortExperiment("...") termina el estudio y muestra el mensaje indicado.

Observá que la última oración del consentimiento cambió. Ya no dice “Si no aceptás, cerrá esta ventana”, porque ahora existe un botón para no aceptar.

18.6 Un criterio de inclusión también puede terminar el estudio

La regla de inclusión tiene la misma forma. La pregunta usa survey-multi-choice y la condición compara el texto de la respuesta.

// Criterio de inclusión: el estudio está dirigido a estudiantes universitarios
const pregunta_estudiante = {
  type: jsPsychSurveyMultiChoice,
  questions: [
    {
      prompt: "¿Estudiás actualmente en la universidad?",
      name: "estudiante",
      options: ["Sí", "No"],
      required: true
    }
  ],
  button_label: "Continuar",
  data: { pantalla: "estudiante" },
  on_finish: function (data) {
    // Si la persona responde "No", no cumple el criterio de inclusión y el estudio termina.
    if (data.response.estudiante === "No") {
      jsPsych.abortExperiment("<p>Este estudio está dirigido a estudiantes universitarios. Muchas gracias por tu interés.</p>");
    }
  }
};

La condición data.response.estudiante === "No" busca dentro de la respuesta la variable estudiante y la compara con el texto "No". El texto debe coincidir exactamente con la opción. Si la opción dijera “no” en minúscula, la comparación con “No” fallaría y la regla nunca se cumpliría.

18.6.1 Una validación y un criterio de inclusión no son lo mismo

La pregunta de edad también expresa un criterio: aceptar personas de 18 a 80 años. Sin embargo, está implementada como validación. Compará qué ocurre en cada caso.

Para la persona, la segunda experiencia es más clara y respetuosa. La primera, además, puede inducir a escribir una edad falsa para poder avanzar. Elegir entre ambas implementaciones es una decisión metodológica y ética. En tu estudio, la validación de edad se mantiene porque también cumple la función de controlar el formato de la respuesta. En el desafío final vas a analizar una alternativa.

18.7 Una pregunta de seguimiento aparece solo si corresponde

Para la tercera regla no hay que terminar el estudio: hay que decidir si una pantalla aparece o no. jsPsych lo resuelve con una línea de tiempo anidada, como la del capítulo anterior, que incluye una función de condición.

// Pregunta de seguimiento: solo aparece si la persona eligió "Herramientas de IA"
const pregunta_herramientas_ia = {
  timeline: [
    {
      type: jsPsychSurveyText,
      questions: [
        { prompt: "¿Qué herramientas de IA usás para estudiar?", name: "herramientas_ia", required: true }
      ],
      button_label: "Continuar",
      data: { pantalla: "herramientas_ia" }
    }
  ],
  conditional_function: function () {
    const recursos = jsPsych.data.get().filter({ pantalla: "recursos" }).values()[0].response.recursos;
    return recursos.includes("Herramientas de IA");
  }
};

El bloque tiene dos partes.

  1. timeline contiene el ensayo de la pregunta, escrito como ya conocés.

  2. conditional_function contiene la regla. jsPsych la ejecuta justo antes de llegar a esta parte de la secuencia. Si la función devuelve verdadero, la pregunta aparece. Si devuelve falso, jsPsych la salta.

Dentro de la función hay dos líneas.

  1. La primera busca la respuesta de la pregunta de recursos. Se lee de izquierda a derecha: de todos los datos, filtrá la fila cuya pantalla es "recursos", tomá la primera y, dentro de su respuesta, la variable recursos. El resultado es la lista de opciones elegidas.

  2. La segunda devuelve el resultado de comprobar si esa lista incluye el texto "Herramientas de IA". La palabra return significa “devolver”.

Observá que la búsqueda usa la etiqueta pantalla que agregaste en el capítulo sobre los datos. Sin esa etiqueta, encontrar la fila correcta sería mucho más difícil.

18.8 Una pregunta que no aplica no es un dato faltante

Cuando la pregunta de seguimiento no aparece, su fila no existe en los datos. Esa ausencia tiene un significado diferente al de un comentario vacío.

  • Un dato faltante es un valor que debería existir y no está. La pregunta se mostró y la persona no respondió.
  • Un valor que no aplica corresponde a una pregunta que, por diseño, no se le hizo a esa persona.

Confundir ambos casos produce errores de análisis. Si alguien calculara el porcentaje de personas que no respondieron sobre herramientas de IA contando a quienes nunca vieron la pregunta, obtendría un número sin sentido. El diccionario de variables debe distinguirlos.

18.9 Este capítulo importa para investigar en Psicología

La lógica condicional implementa decisiones éticas y metodológicas. La salida explícita del consentimiento respeta la decisión de no participar. El criterio de inclusión define la población del estudio. Las preguntas de seguimiento reducen la carga para quien no las necesita.

Cada regla también cambia los datos. Quien no acepta produce un archivo de dos filas. Quien no cumple el criterio, uno de tres. Quien usa herramientas de IA, una fila más que quien no las usa. Antes de recolectar, tenés que saber qué archivo produce cada recorrido.

Decidí qué se registra de quien no participa

Con esta implementación, quien elige “No acepto” produce igualmente un archivo con dos filas: la bienvenida y la respuesta al consentimiento. No contiene respuestas a preguntas ni datos personales, y permite saber cuántas personas decidieron no participar. Aun así, registrar esa decisión es una elección del equipo de investigación. El mensaje final debe describir con exactitud lo que se registró. En la Parte V vas a revisar esta decisión cuando configures el guardado en línea.

18.11 Explicá qué hizo realmente el agente

En los pedidos 1 y 2, el agente agregó una función que se ejecuta al terminar un ensayo. La función compara una respuesta con un valor y, si coinciden, termina el estudio. La decisión sobre qué respuesta termina el estudio, y con qué mensaje, la tomaste vos.

En el pedido 3, el agente envolvió la pregunta en una línea de tiempo anidada y le agregó una condición. Para escribir la condición tuvo que saber dónde encontrar la respuesta de recursos. La encontró gracias a la etiqueta pantalla.

Si el agente escribió la condición de otra forma, por ejemplo con indexOf en lugar de includes, el resultado puede ser equivalente. Lo que no puede cambiar es el texto comparado: debe coincidir exactamente con la opción de la pregunta de recursos.

18.13 Revisá algunas situaciones que suelen causar errores

18.13.1 La regla nunca se cumple

Revisá que el texto o el número comparado coincida exactamente con la respuesta. "no" no es igual a "No", y el botón “No acepto” se registra como 1, no como "No acepto".

18.13.2 La pregunta de seguimiento aparece siempre o nunca

Revisá que el texto de includes coincida exactamente con la opción de la pregunta de recursos, incluidas las mayúsculas.

18.13.3 El estudio termina, pero se muestra una pantalla en blanco

Revisá que abortExperiment reciba el mensaje entre comillas. Abrí la consola con F12 para buscar errores.

18.13.4 La pregunta de seguimiento produce un error en la consola

Si la condición busca la pantalla "recursos" y esa etiqueta no existe, la búsqueda no encuentra ninguna fila. Comprobá que el ensayo de recursos tenga data: { pantalla: "recursos" }.

Las ramas menos frecuentes también las van a recorrer personas reales. Probá cada una.

  1. Una regla condicional tiene una condición, que es lo que se comprueba, y una consecuencia, que es lo que ocurre si la condición se cumple.

  3. Ejecuta instrucciones cuando el ensayo termina.

18.15 Qué aprendiste en este capítulo

La lógica condicional crea ramas en el procedimiento. Cada regla tiene una condición, que depende de un dato previo, y una consecuencia. Dibujar las ramas permite ver todos los recorridos antes de implementarlos.

En jsPsych, on_finish ejecuta instrucciones al terminar un ensayo, if expresa una condición y abortExperiment termina el estudio con un mensaje. Una línea de tiempo anidada con conditional_function muestra una parte de la secuencia solo cuando la condición se cumple.

Una validación y un criterio de inclusión pueden expresar la misma restricción con experiencias muy diferentes para la persona. Una pregunta que no aplica no es un dato faltante, y el diccionario debe distinguirlos.

Cada rama produce un archivo diferente y requiere su propio caso de prueba.
