15  Los datos que genera el estudio

15.1 Objetivos

Al terminar este capítulo vas a poder

  1. describir cómo organiza jsPsych los datos de un estudio;

  2. distinguir el formato largo del formato ancho;

  3. interpretar las columnas principales del archivo de datos;

  4. agregar a los datos una etiqueta por pantalla y un identificador de participante;

  5. descargar los datos como archivo CSV y abrirlos en una planilla de cálculo;

  6. anticipar la estructura de datos que va a producir un estudio antes de recolectarlos.

15.2 Para empezar, una tabla difícil de leer

Al terminar el estudio, la página muestra una tabla de datos en formato CSV. En los capítulos anteriores la usaste para comprobar que cada variable quedaba registrada, pero para un investigador esa tabla tiene tres problemas.

  1. Aparece en la pantalla de quien completa el estudio y se pierde al cerrar la ventana.

  2. Las filas no dicen a qué pantalla corresponden, salvo por su posición.

  3. Nada identifica a la persona que respondió. Si juntaras los datos de veinte personas, no podrías saber qué filas son de quién.

Además, la tabla no se parece a la hoja de cálculo de Google Forms. Ahí había una fila por persona, y acá hay una fila por pantalla.

En este capítulo explicamos esa diferencia y resolvemos los tres problemas. Al terminar, tu estudio va a descargar un archivo de datos que podés abrir en una planilla de cálculo.

Idea clave

Antes de recolectar datos, el investigador tiene que saber qué archivo va a obtener, cuántas filas, qué columnas, qué significa cada valor y cómo se identifica a cada participante. Anticiparlo permite detectar problemas cuando todavía se pueden corregir.

15.3 Una fila por ensayo

Google Forms produce una tabla en formato ancho, con una fila por persona y una columna por variable. jsPsych produce una tabla en formato largo, con una fila por ensayo.

Comparemos las dos organizaciones para una persona que respondió edad y carrera.

Formato ancho (Google Forms)
Marca temporal       | edad | carrera
24/09/2026 10:15:02  | 22   | Psicología
Formato largo (jsPsych)
trial_index | trial_type          | response
0           | html-button-response | 0
1           | survey-html-form     | {"edad":"22"}
2           | survey-text          | {"carrera":"Psicología"}
3           | html-button-response | 0

El formato largo registra todo lo que pasó, pantalla por pantalla, incluso las que no tienen preguntas, como la bienvenida. Es un registro completo del procedimiento. El formato ancho es más cómodo para muchos análisis, y pasar de uno a otro es una tarea del análisis de datos, que se hace con programas como una planilla de cálculo, Jamovi o R. En este libro nos concentramos en entender el formato largo y en documentarlo.

15.4 Qué significa cada columna

El archivo de datos de tu estudio tiene estas columnas principales.

Algunos plugins agregan columnas propias. survey-multi-choice, por ejemplo, agrega response_index, con la posición de cada opción elegida. Cuando una fila es de un plugin que no usa esa columna, la celda queda vacía.

Fijate en la columna rt. Google Forms no registra este dato, y jsPsych lo registra en cada pantalla sin que se lo pidas. En la Parte IV vemos qué información aporta en una encuesta.

15.5 La columna response

En las pantallas de preguntas, la columna response no tiene un único valor, sino un grupo de variables con sus valores, escrito así.

{"genero":"Mujer","anio_carrera":"2.º"}

Esta notación se llama JSON y es una forma estándar de escribir datos como texto. Las llaves { } agrupan pares de nombre y valor, unidos por dos puntos y separados entre sí por comas. Es la misma forma que usás en experiment.js para describir un ensayo, porque JSON viene de JavaScript.

Cuando esta notación aparece dentro de un archivo CSV, las comillas se duplican.

"{""genero"":""Mujer"",""anio_carrera"":""2.º""}"

Las comillas duplicadas no son un error. El formato CSV usa comillas para delimitar cada celda, así que las comillas que forman parte del contenido se escriben dos veces. Una planilla de cálculo las interpreta bien al abrir el archivo.

15.6 Una etiqueta para cada pantalla

Para saber de qué pantalla es una fila, podés mirar trial_index. El problema es que esa posición cambia si agregás o sacás pantallas. Es más estable ponerle una etiqueta a cada ensayo.

Todos los plugins aceptan un parámetro llamado data, y lo que escribas ahí se agrega como columnas en la fila de ese ensayo.

const bienvenida = {
  type: jsPsychHtmlButtonResponse,
  stimulus: "<h1>Estudio sobre hábitos de estudio</h1><p>Gracias por tu interés en participar.</p>",
  choices: ["Comenzar"],
  data: { pantalla: "bienvenida" }
};

Con esa línea, la fila de la bienvenida va a tener una columna pantalla con el valor bienvenida. Si cada ensayo tiene su etiqueta, cada fila del archivo va a decir de qué pantalla es.

15.7 Un identificador para cada participante

Cuando juntes los datos de muchas personas, vas a necesitar saber qué filas son de cada una. Para eso usamos un identificador de participante, que es un código que distingue a cada persona sin revelar quién es.

Un identificador no debe tener datos personales como el nombre, el correo electrónico o el documento. En el capítulo sobre agentes vimos que los datos de participantes necesitan un tratamiento protegido, y un código generado al azar permite distinguir a las personas sin identificarlas.

jsPsych puede generar ese código y agregarlo a todas las filas.

const participante = jsPsych.randomization.randomID(8);
jsPsych.data.addProperties({ participante: participante });

La primera línea genera un código de ocho letras y números al azar, como 8sx0gfol, y lo guarda con el nombre participante. La segunda agrega una columna participante con ese código en todas las filas de datos.

15.8 Descargar un archivo

Hasta ahora, al terminar, el estudio mostraba los datos en pantalla. jsPsych también puede descargar un archivo CSV.

const jsPsych = initJsPsych({
  on_finish: function () {
    jsPsych.data.get().localSave("csv", "datos_" + participante + ".csv");
  }
});

La línea dentro de on_finish junta todos los datos y los guarda en un archivo. El nombre se arma uniendo datos_, el código del participante y la extensión .csv, por ejemplo datos_8sx0gfol.csv. El navegador lo guarda en Descargas, como cualquier descarga.

La descarga sirve para probar, no para recolectar

El archivo se descarga en la computadora de quien completa el estudio. Si una persona participante hiciera esta versión desde su casa, el archivo quedaría en su computadora y a vos no te llegaría. Esta forma de guardado sirve para probar el estudio y revisar sus datos. En la Parte V configuramos un guardado en línea para recolectar datos reales.

15.9 Por qué nos importa en Psicología

La estructura de los datos se decide antes de recolectarlos. Si después de la recolección descubrís que faltaba un identificador o que las filas no se podían interpretar, esos datos pueden quedar inservibles.

Anticipar el archivo de datos es parte del diseño. Antes de publicar un estudio, el investigador debería poder responder qué filas va a tener el archivo de cada participante, qué columnas, qué valores posibles y qué significa un valor vacío. En el próximo capítulo vas a escribir esas respuestas en un diccionario de variables.

15.10 Con Codex

Vas a hacer dos pedidos. El primero agrega las etiquetas de pantalla y el segundo, el identificador y la descarga.

Con Codex

  2. Abrí Codex en mi-primer-estudio con permisos Read Only.

Pedido 1. Etiquetas de pantalla.

En experiment.js, agregá a cada ensayo el parámetro data con una propiedad pantalla.
Usá exactamente estos valores:

En experiment.js:

No modifiques ninguna otra parte del archivo ni otros archivos.
Antes de modificar archivos, explicá qué cambios vas a hacer y esperá mi aprobación.
  1. Revisá el plan y la propuesta. Fijate que la línea displayData se borre y que la línea localSave la reemplace.

Sin acceso a Codex. Hacé los cambios con el editor a partir de los fragmentos de este capítulo. El checkpoint 04-escalas tiene la versión completa de experiment.js.

15.11 Qué hizo el agente

En el primer pedido, el agente agregó la misma estructura a nueve ensayos. Es un cambio repetitivo, de esos que un agente hace muy rápido, y además es fácil de revisar porque cada línea agregada tiene la misma forma. Mirá bien las comas, porque al agregar un parámetro al final de un ensayo, el parámetro anterior necesita una coma al final.

En el segundo pedido, el agente agregó un nombre nuevo, participante, y lo usó en dos lugares, en addProperties y en el nombre del archivo. Fijate que on_finish usa participante aunque está escrito antes en el archivo. Funciona porque lo que está dentro de on_finish recién se ejecuta cuando el estudio termina, y para ese momento participante ya existe.

15.12 Verificar el archivo de datos

Actividad guiada

  1. Recargá el estudio y completalo. Cuando aprietes Finalizar, el navegador va a descargar un archivo.

  2. Abrí la carpeta Descargas y buscá un archivo cuyo nombre empiece con datos_.

  3. Completá el estudio una segunda vez y comprobá que se descargue otro archivo con otro código.

  4. Abrí uno de los archivos en una planilla de cálculo, como Google Sheets, LibreOffice Calc o Excel.

  5. Comprobá que tenga nueve filas de datos, una por pantalla, además de la fila con los nombres de las columnas.

  6. Comprobá que todas las filas tengan el mismo valor en la columna participante.

  7. Comprobá que la columna pantalla tenga un valor distinto en cada fila, en el orden de la línea de tiempo.

  8. Buscá la fila de comentarios y fijate cómo aparece la respuesta vacía.

Para abrir el archivo en Google Sheets, creá una hoja nueva y usá Archivo, Importar y Subir. En LibreOffice Calc, abrilo con doble clic y, en la ventana de importación, elegí la coma como separador y la codificación UTF-8.

15.13 Anticipar la base de datos

Ya podés describir el archivo que produce tu estudio antes de recolectar datos reales.

Archivo:    datos_<participante>.csv, uno por persona
Filas:      9 por persona, una por pantalla
Columnas:   participante, pantalla, rt, response, trial_type, trial_index,
            time_elapsed, stimulus, plugin_version, response_index, question_order
Variables:  edad, genero, anio_carrera, carrera, recursos,
            efoe_1 a efoe_4 y comentarios, dentro de la columna response

Esta descripción ya es una forma de documentación. En el próximo capítulo la convertimos en un diccionario de variables completo.

15.14 Errores frecuentes

15.14.1 El navegador no descarga nada

Algunos navegadores piden permiso para descargar archivos desde una página. Fijate si aparece un aviso en la barra de direcciones, y revisá con la consola, usando F12, que no haya errores.

15.14.2 Todo aparece en una sola columna

La planilla no reconoció la coma como separador. Pasa mucho con Excel configurado en español, que espera punto y coma. Usá la opción de importar datos desde texto y elegí la coma como separador.

15.14.3 Las tildes aparecen como símbolos raros

La planilla leyó el archivo con otra codificación, como vimos en el capítulo sobre cómo describir una tarea. Al importar, elegí UTF-8.

15.14.4 Falta la columna pantalla en alguna fila

Algún ensayo no tiene el parámetro data. Buscá en experiment.js el ensayo que corresponde a esa fila.

15.14.5 El estudio quedó en blanco después de agregar las etiquetas

Seguramente falte una coma antes de la línea data. Abrí la consola con F12, ubicá la línea que indica y revisá la línea anterior.

15.15 Para repasar

Respondé cada pregunta con una oración completa.

  1. ¿Qué diferencia hay entre el formato ancho y el formato largo?

  2. ¿Qué registra la columna rt?

  3. ¿Qué es JSON?

  4. ¿Por qué aparecen comillas duplicadas en el archivo CSV?

  5. ¿Para qué sirve el parámetro data de un ensayo?

  6. ¿Por qué el identificador de participante no debe tener datos personales?

  7. ¿Por qué la descarga local no sirve para recolectar datos de participantes?

  8. ¿Cuántas filas produce cada participante en la versión actual del estudio?

Ver respuestas posibles

  1. En formato ancho hay una fila por persona, mientras que en formato largo hay una fila por ensayo.

  2. Registra los milisegundos desde que apareció la pantalla hasta que la persona avanzó.

  3. JSON es una forma estándar de escribir datos como texto, con pares de nombre y valor entre llaves.

  4. El formato CSV usa comillas para delimitar las celdas, por lo que las comillas del contenido se escriben dos veces.

  5. Agrega columnas con información propia a la fila de datos de ese ensayo.

  6. El identificador debe distinguir a las personas sin permitir saber quiénes son, para proteger su privacidad.

  7. El archivo se descarga en la computadora de quien completa el estudio, no en la del investigador.

  8. Cada participante produce nueve filas.

15.16 En síntesis

jsPsych registra los datos en formato largo, con una fila por ensayo, mientras que Google Forms usa formato ancho, con una fila por persona. Son dos formas distintas de organizar los mismos datos.

Cada fila tiene columnas como rt, response, trial_type y time_elapsed. En las preguntas, la columna response agrupa las variables con sus valores en notación JSON.

Con el parámetro data etiquetamos cada ensayo. randomID y addProperties agregan un identificador de participante a todas las filas, sin datos personales. localSave descarga los datos como archivo CSV, lo que sirve para probar el estudio pero no para recolectar datos reales.

Anticipar la estructura del archivo de datos es parte del diseño del estudio.

15.17 Desafío

Imaginá que sumás al estudio una pantalla nueva, con dos preguntas de opción múltiple sobre horas de sueño, entre la escala y los comentarios.

  1. Decí cuántas filas va a producir cada participante con ese cambio.

  2. Proponé una etiqueta de pantalla y dos nombres de variable para las preguntas nuevas.

  3. Escribí cómo se vería la columna response de esa pantalla para alguien que eligió “Entre 6 y 8 horas” y “Sí”.

  4. Decí qué valor tendría trial_index para la pantalla de comentarios después del cambio.

  5. Explicá por qué la etiqueta pantalla es más estable que trial_index para identificar filas.
