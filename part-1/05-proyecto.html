5  Cómo se organiza un proyecto

5.1 Qué vas a poder hacer

Al terminar este capítulo, vas a poder realizar las siguientes acciones.

  1. Vas a poder explicar qué convierte una carpeta en un proyecto.

  2. Vas a poder reconocer la carpeta principal de un proyecto.

  3. Vas a poder distinguir la documentación, los materiales, las instrucciones y los datos.

  4. Vas a poder explicar qué funciones cumplen README.md y AGENTS.md.

  5. Vas a poder crear la primera versión de mi-primer-estudio.

  6. Vas a poder verificar su ubicación, su estructura y su documentación.

  7. Vas a poder explicar para qué sirve un checkpoint.

5.2 Varios archivos dispersos permiten formular el problema

Imaginá que comenzás a preparar un estudio sobre hábitos de estudio. Guardás una consigna en Documentos. Descargás una imagen en Descargas. Escribís posibles preguntas en un archivo llamado ideas final.docx. Después creás otra versión llamada ideas final 2.docx.

Una semana más tarde necesitás continuar. Recordás el tema general, pero aparecen preguntas concretas.

  1. ¿Qué archivo contiene la versión actual?

  2. ¿Qué imagen forma parte del estudio?

  3. ¿Dónde se guardarán las respuestas?

  4. ¿Qué decisiones ya fueron tomadas?

  5. ¿Qué tareas quedan pendientes?

Los archivos existen, pero su relación depende de tu memoria. Otra persona tendría dificultades para comprenderlos. Un agente también carecería de un punto de partida claro.

Un proyecto organiza esas relaciones. Reúne los archivos vinculados con un propósito y conserva información que permite interpretarlos.

Un proyecto vincula un propósito con una organización verificable

La carpeta principal delimita los archivos. La documentación explica el objetivo y el estado. La estructura permite encontrar cada elemento y comprobar los cambios.

5.3 Un proyecto reúne trabajo relacionado

Un proyecto es un conjunto organizado de archivos y carpetas que comparten un propósito. Puede representar un informe, una aplicación, un análisis o un estudio psicológico digital.

La organización cumple varias funciones.

  1. Mantiene juntos los archivos que participan en el mismo trabajo.

  2. Permite reconocer qué función cumple cada archivo.

  3. Conserva instrucciones para continuar la tarea.

  4. Facilita la revisión de los cambios.

  5. Ayuda a trasladar el trabajo a otra computadora.

Una carpeta adquiere sentido como proyecto cuando su contenido responde a un objetivo compartido y puede interpretarse mediante su estructura y su documentación.

Durante el curso vas a construir un proyecto llamado mi-primer-estudio. Su propósito será aprender a diseñar, implementar y verificar un estudio psicológico digital. La estructura crecerá cuando cada etapa necesite nuevos archivos.

5.4 La carpeta principal delimita el proyecto

La carpeta que contiene el proyecto completo recibe el nombre de carpeta principal. En documentación técnica también vas a encontrar las expresiones raíz del proyecto y project root.

En la primera etapa, la estructura será pequeña.

mi-primer-estudio/
    README.md

La carpeta mi-primer-estudio es la carpeta principal. El archivo README.md se encuentra directamente dentro de ella.

Esta ubicación importa. Más adelante, algunas herramientas buscarán archivos especiales a partir de la raíz. Un agente que comienza a trabajar allí podrá inspeccionar el contenido del proyecto y leer sus instrucciones.

La carpeta principal también funciona como referencia para las rutas relativas. Cuando la ubicación actual es mi-primer-estudio, la ruta relativa README.md identifica el archivo de documentación.

La carpeta principal define el alcance inicial del trabajo

Antes de ejecutar una herramienta o iniciar un agente, comprobá que PowerShell se encuentre en la carpeta principal del proyecto. Get-Location muestra la ubicación y dir muestra su contenido.

5.5 Los archivos cumplen funciones diferentes

Un proyecto de investigación puede reunir varios tipos de contenido. Cada tipo responde a una necesidad.

5.5.1 La documentación explica el trabajo

La documentación describe el propósito, el estado, las decisiones y los pasos necesarios para usar o revisar el proyecto.

En esta primera etapa, README.md será el único archivo. Su contenido explicará por qué existe el proyecto y qué incluye actualmente.

5.5.2 Las instrucciones definen el comportamiento del estudio

Más adelante aparecerán archivos con instrucciones que el navegador podrá ejecutar. Esas instrucciones controlarán preguntas, estímulos, tiempos y respuestas. Con frecuencia reciben el nombre de código.

El código es texto escrito según reglas que un programa puede interpretar. Este libro introducirá esas reglas de manera progresiva. Primero vas a aprender a leer, localizar y verificar cambios pequeños.

5.5.3 Los materiales aportan contenido al procedimiento

Las imágenes, los sonidos, los textos y otros estímulos forman parte de los materiales. Su selección depende del diseño metodológico y de los permisos para utilizarlos.

5.5.4 Los datos registran interacciones y resultados

Las respuestas, los tiempos y las condiciones asignadas pueden convertirse en datos. Su ubicación, su estructura y su protección requieren decisiones explícitas.

5.5.5 La configuración orienta a las herramientas

Algunos archivos indican cómo debe ejecutarse, revisarse o publicarse un proyecto. Esos archivos aparecerán cuando hagan falta. Incorporarlos antes de comprender su función agregaría complejidad innecesaria.

Por ahora, una carpeta y un archivo de documentación resultan suficientes.

5.6 README.md presenta el proyecto a una persona

El nombre README puede leerse como una invitación en inglés: “leeme”. Un archivo con ese nombre suele presentar el proyecto y explicar cómo comenzar.

La extensión .md indica que el archivo utiliza Markdown. Markdown es una forma de escribir texto plano y señalar títulos, enlaces u otros elementos mediante caracteres visibles.

El texto plano contiene caracteres que muchos programas pueden abrir. No depende de un formato exclusivo de Word. El Bloc de notas y otros editores gratuitos pueden modificarlo.

GitHub es un servicio web que permite alojar y compartir proyectos. Lo utilizaremos en una etapa posterior del curso. GitHub reconoce los archivos README.md y suele mostrarlos al entrar en un proyecto. Su documentación sobre archivos README recomienda incluir información como el propósito, la utilidad y la forma de comenzar.

Un README inicial puede responder cuatro preguntas.

  1. ¿Cómo se llama el proyecto?

  2. ¿Qué propósito tiene?

  3. ¿En qué estado se encuentra?

  4. ¿Cuál será el próximo paso?

Durante este capítulo vas a escribir respuestas breves y verificables.

5.7 Markdown permite marcar títulos con caracteres visibles

Observá este ejemplo.

# Mi primer estudio psicológico

## Este proyecto tiene un propósito

Este proyecto permitirá aprender a construir y verificar un estudio psicológico digital.

El primer signo # marca el título principal. Los dos signos ## marcan un título interno. La línea restante contiene un párrafo.

Los signos forman parte del archivo de texto. Un programa capaz de interpretar Markdown puede mostrarlos como títulos con distinto tamaño. Un editor básico puede mostrarlos como caracteres comunes. El contenido se conserva en ambos casos.

En esta etapa necesitás reconocer solamente esos dos niveles. Las demás posibilidades de Markdown aparecerán cuando ayuden a documentar una tarea concreta.

5.8 AGENTS.md orientará el trabajo de los agentes

Más adelante, el proyecto incorporará un archivo llamado AGENTS.md. Su función será comunicar instrucciones estables a los agentes que trabajen dentro del proyecto.

Ese archivo podrá indicar quiénes usarán el estudio, qué términos deben explicarse, qué archivos requieren cuidado y qué verificaciones deben realizarse después de una modificación.

README.md presenta el proyecto y ayuda a las personas a comprenderlo. AGENTS.md establece reglas de trabajo para los agentes. Ambos archivos pueden compartir información, aunque cumplen funciones diferentes.

En el siguiente capítulo vas a estudiar qué cambia cuando una IA puede leer archivos y realizar acciones. El archivo AGENTS.md se incorporará cuando esa función resulte necesaria.

5.9 El proyecto técnico representa decisiones metodológicas

La carpeta organiza una implementación. El estudio comienza con decisiones de investigación que necesitan quedar documentadas.

Una decisión metodológica define qué se quiere investigar y bajo qué condiciones. Por ejemplo, el investigador decide qué constructo estudiar, quiénes pueden participar, qué procedimiento se utilizará y qué variable representará cada respuesta.

Una decisión técnica define cómo se realizará una parte del procedimiento mediante archivos y programas. Por ejemplo, el equipo decide qué nombre tendrá una variable, dónde estará una imagen y qué archivo controlará una pantalla.

Las decisiones se relacionan. El nombre técnico edad puede representar la edad informada por una persona. El rango permitido debe surgir de los criterios metodológicos del estudio.

El proyecto necesita registrar ambas capas. La ejecución permite comprobar la implementación técnica. El protocolo, la documentación y la revisión del investigador permiten evaluar la correspondencia metodológica.

La estructura ordenada todavía necesita contenido válido

Una carpeta puede contener archivos bien nombrados y un programa puede ejecutarse correctamente. La calidad metodológica depende de las decisiones que esos archivos implementan.

5.10 El proyecto crecerá cuando aparezca una necesidad

El proyecto inicial contiene un solo archivo. Esa restricción permite concentrarse en el propósito, la ubicación y la verificación.

En una etapa posterior aparecerán archivos para mostrar el estudio en un navegador.

mi-primer-estudio/
    index.html
    experiment.js
    README.md

Esa estructura se introducirá cuando el curso explique qué función cumple cada archivo. Más adelante también podrán aparecer carpetas para materiales, estilos y componentes del estudio.

Agregar archivos de forma gradual permite comprender por qué existe cada elemento. También facilita la detección de errores. Cuando una etapa pequeña funciona, el siguiente cambio tiene un punto de partida conocido.

5.11 Un checkpoint conserva una etapa recuperable

Un checkpoint es una copia del proyecto guardada en un momento concreto del recorrido. Cada checkpoint de este curso funciona de manera independiente y representa una etapa terminada.

El primer checkpoint contiene solamente README.md.

proyectos/
    01-inicial/
        README.md

El número 01 indica la posición dentro de la secuencia. La palabra inicial describe la etapa.

Los checkpoints permiten comparar el trabajo propio con una versión de referencia. También permiten continuar si una versión posterior deja de funcionar. La recuperación consiste en copiar una etapa conocida y trabajar sobre la copia.

La versión de referencia debe conservarse sin cambios durante las actividades. Tu trabajo cotidiano ocurrirá dentro de mi-primer-estudio.

Un checkpoint ofrece un punto de recuperación

Cuando una práctica produce cambios difíciles de comprender, podés volver a una etapa funcional. Después podés repetir un cambio por vez y verificar cada resultado.

5.12 Creá la primera versión del proyecto

Realizá esta actividad guiada

Primero vas a crear la carpeta principal.

  1. Elegí una ubicación que puedas encontrar con facilidad. Podés usar Documentos o una carpeta destinada al curso.

  2. Creá una carpeta llamada mi-primer-estudio.

  3. Abrí esa carpeta y comprobá que se encuentre vacía.

Después vas a crear la documentación.

  1. Abrí el Bloc de notas u otro editor de texto plano.

  2. Copiá el siguiente contenido.

# Mi primer estudio psicológico

## Este proyecto tiene un propósito

Este proyecto permitirá aprender a diseñar, construir y verificar un estudio psicológico digital.

## El proyecto se encuentra en su etapa inicial

La carpeta contiene únicamente este archivo de documentación. Todavía no presenta preguntas ni recolecta datos.

## El próximo paso incorporará nuevas herramientas

El proyecto incorporará archivos e instrucciones de manera gradual durante el curso.

  1. Elegí la opción para guardar el archivo dentro de mi-primer-estudio.

  2. Escribí el nombre completo README.md.

  3. Si el editor ofrece una opción para elegir el tipo de archivo, seleccioná una alternativa que conserve el nombre completo, como Todos los archivos.

  4. Cerrá el editor y activá la visualización de extensiones en el Explorador de archivos.

  5. Comprobá que el archivo se llame README.md.

Finalmente vas a verificar el proyecto desde PowerShell.

  1. Copiá la ruta de mi-primer-estudio desde la barra de direcciones del Explorador.

  2. Abrí PowerShell.

  3. Escribí cd, agregá un espacio y pegá la ruta entre comillas.

  4. Ejecutá Get-Location y comprobá que la ruta termine en mi-primer-estudio.

  5. Ejecutá dir y comprobá que aparezca README.md.

  6. Abrí README.md y comprobá que el contenido se haya conservado.

  7. Cerrá el archivo, cerrá PowerShell y volvé a encontrar el proyecto desde el Explorador.

5.13 Explicá qué ocurrió durante la actividad

Creaste una carpeta principal con un propósito definido. El nombre mi-primer-estudio permite reconocerla. Su ubicación completa permite distinguirla de otras carpetas que podrían compartir el mismo nombre.

El editor creó un archivo de texto plano. La extensión .md indicó que su contenido utiliza Markdown. Los títulos y los párrafos documentaron el propósito, el estado y el próximo paso.

PowerShell permitió verificar dos condiciones. Get-Location confirmó la ubicación. dir confirmó la estructura. La apertura final del archivo confirmó el contenido.

La verificación reunió tres preguntas diferentes.

  1. ¿Creé el proyecto en la ubicación prevista?

  2. ¿La carpeta contiene el archivo previsto?

  3. ¿El archivo contiene la información prevista?

Responder las tres preguntas aporta más evidencia que observar únicamente el nombre de la carpeta.

5.14 El primer checkpoint permite comparar y recuperar

Este libro incluye una versión de referencia dentro de proyectos\01-inicial. Esa carpeta contiene el estado esperado al finalizar este capítulo.

Si tenés acceso a los archivos del curso, podés abrir ese checkpoint y comparar su estructura con mi-primer-estudio. La redacción puede presentar pequeñas diferencias si personalizaste el propósito. La estructura debe contener un archivo llamado README.md dentro de la carpeta principal.

Conservá 01-inicial como referencia. Si una actividad futura daña tu proyecto, copiá el checkpoint en otra ubicación y asignale un nombre nuevo. Después repetí solamente los cambios que ya comprendés.

La recuperación también forma parte de una práctica responsable de investigación. Una versión identificable permite reconstruir qué procedimiento estaba disponible en una etapa determinada.

5.15 Una revisión puede anticipar los datos futuros

El proyecto todavía no recolecta respuestas. Sin embargo, ya podés practicar una pregunta que acompañará todo el curso: ¿qué datos producirá este estudio?

Imaginá que más adelante agregás una pregunta de edad. La especificación podría incluir estas oraciones.

  1. El estudio registrará la respuesta con el nombre edad.

  2. La respuesta tendrá un valor numérico.

  3. La respuesta aceptará valores entre 18 y 80.

  4. El procedimiento indicará qué debe ocurrir cuando una persona deja el campo vacío.

Estas decisiones todavía no forman parte del proyecto inicial. El ejemplo muestra cómo una intención de investigación necesita convertirse en una especificación verificable antes de implementar una pregunta.

Más adelante, el README podrá registrar qué variables produce el estudio y dónde encontrar su definición completa.

5.16 La documentación permite que otra persona continúe

Un proyecto necesita ser comprensible después de una pausa. También necesita permitir una revisión realizada por otra persona.

Considerá dos descripciones posibles.

Proyecto para la facultad.
Este proyecto permitirá aprender a diseñar, construir y verificar un estudio psicológico digital.

La segunda oración comunica una finalidad concreta. Todavía puede ampliarse, pero ofrece un criterio para evaluar los próximos cambios.

Cuando una persona lea el README, debería poder reconocer el objetivo general y el estado actual. Cuando un agente lo lea, tendrá contexto para interpretar los archivos. La documentación reduce la dependencia de la memoria de quien creó el proyecto.

5.17 Comprobá lo que comprendiste

Respondé cada pregunta con una oración completa.

  1. ¿Qué relación comparten los archivos de un proyecto?

  2. ¿Qué significa la expresión “carpeta principal”?

  3. ¿Qué función cumple README.md?

  4. ¿Qué información comunicará AGENTS.md en una etapa posterior?

  5. ¿Qué indica la extensión .md?

  6. ¿Qué tres aspectos verificaste después de crear el proyecto?

  7. ¿Para qué sirve un checkpoint?

  8. ¿Por qué una estructura correcta todavía requiere una revisión metodológica?

Consultá una posible respuesta después de resolver la actividad.

  1. Los archivos de un proyecto comparten un propósito y una organización.

  2. La carpeta principal contiene el proyecto completo y funciona como referencia para su estructura.

  3. README.md presenta el proyecto y documenta su propósito, su estado y la forma de comenzar.

  4. AGENTS.md comunicará reglas estables para los agentes que trabajen dentro del proyecto.

  5. La extensión .md indica que el archivo utiliza Markdown.

  6. Verifiqué la ubicación, la estructura y el contenido.

  7. Un checkpoint conserva una etapa recuperable y permite comparar el trabajo con una versión conocida.

  8. La estructura organiza la implementación, mientras que la revisión metodológica evalúa las decisiones de investigación representadas por esa implementación.

5.18 Revisá algunas situaciones que suelen causar confusión

5.18.1 El archivo puede terminar con una extensión adicional

Algunos editores agregan .txt de manera automática. Activá la visualización de extensiones y comprobá que el nombre sea README.md en lugar de README.md.txt.

5.18.2 La carpeta puede quedar dentro de otra carpeta con el mismo nombre

Comprobá la ruta completa. La estructura esperada contiene una carpeta principal y el archivo directamente dentro de ella.

mi-primer-estudio/
    README.md

5.18.3 Una copia dispersa puede confundirse con el proyecto actual

Evitá crear varias carpetas llamadas mi-primer-estudio en ubicaciones distintas. Cuando exista más de una copia, documentá cuál representa el trabajo actual y cuál funciona como respaldo.

5.18.4 Un README demasiado general aporta poco contexto

Escribí qué permitirá hacer el proyecto y en qué estado se encuentra. Las expresiones concretas ayudan a evaluar si una modificación corresponde al objetivo.

5.18.5 La estructura completa del curso todavía resultaría prematura

Cada archivo aparecerá cuando puedas explicar su función. La estructura inicial mantiene visible todo el proyecto y facilita su verificación.

5.18.6 El checkpoint de referencia debe permanecer recuperable

Realizá las actividades dentro de mi-primer-estudio. Usá proyectos\01-inicial para comparar o copiar una base nueva.

5.19 Qué aprendiste en este capítulo

Un proyecto reúne archivos y carpetas que comparten un propósito. La carpeta principal delimita el trabajo y funciona como referencia para las rutas relativas.

Los archivos pueden documentar, implementar instrucciones, aportar materiales, registrar datos o configurar herramientas. La estructura crece cuando el proyecto necesita cumplir una función nueva.

README.md presenta el proyecto mediante texto en formato Markdown. AGENTS.md comunicará reglas estables a los agentes en una etapa posterior.

El proyecto inicial contiene solamente README.md. Get-Location permite verificar la ubicación. dir permite verificar la estructura. La lectura del archivo permite verificar el contenido.

Un checkpoint conserva una etapa recuperable. La primera referencia del curso se encuentra en proyectos\01-inicial.

La organización técnica ayuda a implementar y revisar el estudio. Las decisiones metodológicas determinan qué debe representar esa organización.

5.20 Resolvé un desafío breve

Pedile a otra persona que revise mi-primer-estudio sin explicarle previamente cómo lo creaste.

  1. La persona debe encontrar la carpeta a partir de la ubicación que le indiques.

  2. La persona debe identificar el propósito mediante README.md.

  3. La persona debe describir el estado actual del proyecto.

  4. La persona debe indicar cuál será el próximo paso.

  5. La persona debe confirmar que el proyecto todavía no recolecta datos.

Registrá cualquier pregunta que la documentación haya dejado sin respuesta. Después agregá al README una oración que resuelva esa duda y volvé a realizar la revisión.

Con este proyecto termina la Parte I. En la Parte II vas a estudiar cómo trabaja un agente de IA sobre una carpeta, qué acciones puede realizar y qué decisiones debe conservar el investigador.
