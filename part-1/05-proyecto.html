5  Qué es un proyecto

5.1 Objetivos

Al terminar este capítulo vas a poder

  1. explicar qué convierte a una carpeta en un proyecto;

  2. reconocer la carpeta principal de un proyecto;

  3. distinguir documentación, materiales, instrucciones y datos;

  4. explicar para qué sirven README.md y AGENTS.md;

  5. crear la primera versión de mi-primer-estudio;

  6. verificar su ubicación, su estructura y su documentación;

  7. explicar para qué sirve un checkpoint.

5.2 Para empezar, archivos por todos lados

Imaginá que empezás a preparar un estudio sobre hábitos de estudio. Guardás una consigna en Documentos, bajás una imagen que queda en Descargas y anotás algunas preguntas en un archivo llamado ideas final.docx. Después hacés otra versión, ideas final 2.docx.

Una semana más tarde querés retomar. Te acordás del tema general, pero aparecen preguntas concretas.

  1. ¿Qué archivo tiene la versión actual?

  2. ¿Qué imagen es parte del estudio?

  3. ¿Dónde se van a guardar las respuestas?

  4. ¿Qué decisiones ya tomaste?

  5. ¿Qué te falta hacer?

Los archivos están, pero cómo se relacionan entre sí depende de tu memoria. Otra persona tendría problemas para entenderlos, y un agente no tendría un punto de partida claro.

Un proyecto ordena esas relaciones. Junta los archivos que tienen un mismo propósito y guarda la información necesaria para entenderlos.

Idea clave

La carpeta principal marca qué archivos son parte del trabajo. La documentación explica el objetivo y el estado. La estructura te deja encontrar cada cosa y comprobar los cambios.

5.3 Qué es un proyecto

Un proyecto es un conjunto ordenado de archivos y carpetas que comparten un propósito. Puede ser un informe, una aplicación, un análisis o un estudio psicológico online.

Esa organización nos sirve para varias cosas.

  1. Mantener juntos los archivos del mismo trabajo.

  2. Saber qué función cumple cada archivo.

  3. Guardar indicaciones para poder retomar la tarea.

  4. Revisar los cambios con más facilidad.

  5. Llevar el trabajo a otra computadora.

Una carpeta se vuelve un proyecto cuando su contenido responde a un objetivo común y se puede entender a partir de su estructura y su documentación.

Durante el curso vas a construir un proyecto llamado mi-primer-estudio. Su propósito es aprender a diseñar, implementar y verificar un estudio psicológico online. La estructura va a ir creciendo a medida que cada etapa necesite archivos nuevos.

5.4 La carpeta principal

A la carpeta que contiene todo el proyecto la llamamos carpeta principal. En la documentación técnica también vas a encontrar raíz del proyecto o project root.

En la primera etapa la estructura es chiquita.

mi-primer-estudio/
    README.md

mi-primer-estudio es la carpeta principal y README.md está directamente adentro.

Esa ubicación importa. Más adelante algunas herramientas van a buscar ciertos archivos a partir de la raíz, y un agente que arranca a trabajar ahí va a poder revisar el contenido del proyecto y leer sus instrucciones.

La carpeta principal también es la referencia de las rutas relativas. Si estás parado en mi-primer-estudio, la ruta relativa README.md apunta al archivo de documentación.

Empezá siempre desde la carpeta principal

Antes de ejecutar una herramienta o abrir un agente, comprobá que PowerShell esté en la carpeta principal del proyecto. Get-Location te muestra dónde estás y dir te muestra qué hay.

5.5 Qué tipo de archivos hay en un proyecto

Un proyecto de investigación puede juntar distintos tipos de contenido, y cada uno responde a una necesidad.

5.5.1 Documentación

Describe el propósito, el estado, las decisiones y los pasos para usar o revisar el proyecto.

En esta primera etapa README.md va a ser el único archivo. Ahí vamos a explicar por qué existe el proyecto y qué tiene por ahora.

5.5.2 Instrucciones

Más adelante van a aparecer archivos con instrucciones que el navegador puede ejecutar. Esas instrucciones controlan preguntas, estímulos, tiempos y respuestas, y en general se las llama código.

El código es texto escrito siguiendo reglas que un programa puede interpretar. Vamos a ir presentando esas reglas de a poco. Primero vas a aprender a leer, a encontrar cosas y a verificar cambios chicos.

5.5.3 Materiales

Las imágenes, los sonidos, los textos y otros estímulos son materiales. Cuáles usamos depende del diseño metodológico y de los permisos que tengamos para usarlos.

5.5.4 Datos

Las respuestas, los tiempos y las condiciones asignadas pueden convertirse en datos. Dónde se guardan, cómo se organizan y cómo se protegen son decisiones que hay que tomar de forma explícita.

5.5.5 Configuración

Algunos archivos indican cómo ejecutar, revisar o publicar un proyecto. Los vamos a agregar cuando hagan falta, porque sumarlos antes de entender para qué sirven solo complica las cosas.

Por ahora, con una carpeta y un archivo de documentación alcanza.

5.6 El README.md

README se puede leer como una invitación en inglés, “leeme”. Un archivo con ese nombre suele presentar el proyecto y explicar cómo empezar.

La extensión .md indica que el archivo usa Markdown, que es una forma de escribir texto plano marcando títulos, enlaces y otros elementos con caracteres visibles.

El texto plano tiene caracteres que casi cualquier programa puede abrir, sin depender de un formato propio de Word. Lo podés modificar con el Bloc de notas o con otros editores gratuitos.

GitHub es un servicio web para alojar y compartir proyectos. Lo vamos a usar más adelante en el curso. GitHub reconoce los archivos README.md y suele mostrarlos cuando entrás a un proyecto. En su documentación sobre archivos README recomienda contar para qué sirve el proyecto, qué utilidad tiene y cómo empezar a usarlo.

Un README inicial puede responder cuatro preguntas.

  1. ¿Cómo se llama el proyecto?

  2. ¿Para qué sirve?

  3. ¿En qué estado está?

  4. ¿Cuál es el próximo paso?

En este capítulo vas a escribir respuestas cortas y que se puedan comprobar.

5.7 Títulos en Markdown

Mirá este ejemplo.

# Mi primer estudio psicológico

## Este proyecto tiene un propósito

Este proyecto permitirá aprender a construir y verificar un estudio psicológico digital.

Un signo # marca el título principal y dos signos ## marcan un título interno. La última línea es un párrafo.

Esos signos son parte del archivo de texto. Un programa que entiende Markdown los muestra como títulos de distinto tamaño, y un editor básico los muestra como caracteres comunes. En los dos casos el contenido es el mismo.

Por ahora alcanza con reconocer esos dos niveles. El resto de lo que permite Markdown lo vamos a ver cuando nos ayude a documentar algo concreto.

5.8 El AGENTS.md

Más adelante vamos a sumar al proyecto un archivo llamado AGENTS.md. Sirve para darles instrucciones estables a los agentes que trabajen en el proyecto.

Ahí podemos indicar quiénes van a usar el estudio, qué términos hay que explicar, qué archivos piden cuidado y qué verificaciones hacer después de cada cambio.

README.md presenta el proyecto y ayuda a las personas a entenderlo. AGENTS.md fija reglas de trabajo para los agentes. Pueden compartir información, pero cumplen funciones distintas.

En el próximo capítulo vemos qué cambia cuando una IA puede leer archivos y hacer cosas. AGENTS.md va a aparecer cuando lo necesitemos.

5.9 Decisiones metodológicas y decisiones técnicas

La carpeta organiza una implementación, pero el estudio empieza con decisiones de investigación que tienen que quedar documentadas.

Una decisión metodológica define qué queremos investigar y en qué condiciones. Por ejemplo, qué constructo estudiar, quiénes pueden participar, qué procedimiento usar y qué variable va a representar cada respuesta.

Una decisión técnica define cómo se lleva a cabo una parte del procedimiento con archivos y programas. Por ejemplo, qué nombre tiene una variable, dónde está una imagen o qué archivo controla una pantalla.

Unas y otras se relacionan. El nombre técnico edad puede representar la edad que informa una persona, pero el rango permitido tiene que salir de los criterios metodológicos del estudio.

El proyecto tiene que registrar las dos capas. Ejecutar el estudio nos permite comprobar la implementación técnica. El protocolo, la documentación y la revisión del investigador nos permiten evaluar si esa implementación corresponde a lo que decidimos.

Ordenado no quiere decir válido

Una carpeta puede tener archivos con buenos nombres y un programa puede ejecutarse perfecto. La calidad metodológica depende de las decisiones que esos archivos implementan.

5.10 Un proyecto que crece cuando hace falta

El proyecto inicial tiene un solo archivo. Esa limitación nos deja concentrarnos en el propósito, la ubicación y la verificación.

Más adelante van a aparecer archivos para mostrar el estudio en el navegador.

mi-primer-estudio/
    index.html
    experiment.js
    README.md

Esa estructura la vamos a presentar cuando expliquemos qué hace cada archivo. Después pueden aparecer también carpetas para materiales, estilos y partes del estudio.

Sumar archivos de a poco ayuda a entender por qué existe cada uno, y también a encontrar errores. Si una etapa chica funciona, el siguiente cambio parte de algo conocido.

5.11 Los checkpoints

Un checkpoint es una copia del proyecto guardada en un momento concreto del recorrido. Cada checkpoint del curso funciona por su cuenta y representa una etapa terminada.

El primero tiene solo README.md.

proyectos/
    01-inicial/
        README.md

El número 01 marca la posición en la secuencia y la palabra inicial describe la etapa.

Con los checkpoints podés comparar tu trabajo con una versión de referencia, y también seguir adelante si una versión posterior deja de funcionar. Para recuperarte, copiás una etapa conocida y trabajás sobre esa copia.

La versión de referencia no se toca durante las actividades. Tu trabajo de todos los días va dentro de mi-primer-estudio.

Un lugar al que volver

Si una práctica te deja cambios que no entendés, podés volver a una etapa que funcionaba. Después repetís los cambios de a uno y verificás cada resultado.

5.12 Actividad

Actividad guiada

Primero vas a crear la carpeta principal.

  1. Elegí un lugar que puedas encontrar fácil, como Documentos o una carpeta para el curso.

  2. Creá una carpeta llamada mi-primer-estudio.

  3. Abrila y comprobá que esté vacía.

Después vas a crear la documentación.

  1. Abrí el Bloc de notas u otro editor de texto plano.

  2. Copiá este contenido.

# Mi primer estudio psicológico

## Este proyecto tiene un propósito

Este proyecto permitirá aprender a diseñar, construir y verificar un estudio psicológico digital.

## El proyecto se encuentra en su etapa inicial

La carpeta contiene únicamente este archivo de documentación. Todavía no presenta preguntas ni recolecta datos.

## El próximo paso incorporará nuevas herramientas

El proyecto incorporará archivos e instrucciones de manera gradual durante el curso.

  1. Elegí la opción para guardar el archivo dentro de mi-primer-estudio.

  2. Escribí el nombre completo README.md.

  3. Si el editor te deja elegir el tipo de archivo, elegí una opción que respete el nombre completo, como Todos los archivos.

  4. Cerrá el editor y activá la visualización de extensiones en el Explorador de archivos.

  5. Comprobá que el archivo se llame README.md.

Por último vas a verificar el proyecto desde PowerShell.

  1. Copiá la ruta de mi-primer-estudio desde la barra de direcciones del Explorador.

  2. Abrí PowerShell.

  3. Escribí cd, dejá un espacio y pegá la ruta entre comillas.

  4. Ejecutá Get-Location y comprobá que la ruta termine en mi-primer-estudio.

  5. Ejecutá dir y comprobá que aparezca README.md.

  6. Abrí README.md y comprobá que el contenido esté completo.

  7. Cerrá el archivo, cerrá PowerShell y volvé a encontrar el proyecto desde el Explorador.

5.13 Qué pasó en la actividad

Creaste una carpeta principal con un propósito definido. El nombre mi-primer-estudio te permite reconocerla y su ubicación completa la distingue de otras carpetas que podrían llamarse igual.

El editor creó un archivo de texto plano. La extensión .md indica que usa Markdown, y los títulos y párrafos documentan el propósito, el estado y el próximo paso.

Con PowerShell comprobaste dos cosas. Get-Location confirmó la ubicación y dir confirmó la estructura. Al abrir el archivo al final, confirmaste también el contenido.

En definitiva, la verificación respondió tres preguntas distintas.

  1. ¿Creé el proyecto donde quería?

  2. ¿La carpeta tiene el archivo que tiene que tener?

  3. ¿El archivo tiene la información que tiene que tener?

Responder las tres da mucha más evidencia que mirar solo el nombre de la carpeta.

5.14 Comparar con el primer checkpoint

El libro trae una versión de referencia en proyectos\01-inicial, con el estado esperado al terminar este capítulo.

Si tenés los archivos del curso, abrí ese checkpoint y compará su estructura con mi-primer-estudio. Si personalizaste el propósito, la redacción puede cambiar un poco, pero la estructura tiene que ser la misma, con un README.md dentro de la carpeta principal.

Guardá 01-inicial como referencia. Si una actividad futura rompe tu proyecto, copiá el checkpoint en otro lugar, ponele un nombre nuevo y repetí solo los cambios que ya entendés.

Poder recuperar versiones también es parte de investigar de forma responsable. Una versión identificable permite reconstruir qué procedimiento había en una etapa determinada.

5.15 Pensar en los datos desde ahora

El proyecto todavía no recolecta respuestas, pero ya podemos practicar una pregunta que nos va a acompañar todo el curso. ¿Qué datos va a producir este estudio?

Imaginá que más adelante agregás una pregunta de edad. La especificación podría decir algo así.

  1. El estudio va a registrar la respuesta con el nombre edad.

  2. La respuesta va a ser un número.

  3. Se van a aceptar valores entre 18 y 80.

  4. El procedimiento va a indicar qué pasa si una persona deja el campo vacío.

Nada de esto forma parte todavía del proyecto inicial. El ejemplo muestra cómo una intención de investigación tiene que convertirse en una especificación que se pueda verificar antes de programar una pregunta.

Más adelante el README puede registrar qué variables produce el estudio y dónde está su definición completa.

5.16 Documentar para que otro pueda seguir

Un proyecto tiene que poder entenderse después de una pausa, y también tiene que poder revisarlo otra persona.

Compará estas dos descripciones.

Proyecto para la facultad.
Este proyecto permitirá aprender a diseñar, construir y verificar un estudio psicológico digital.

La segunda dice para qué es el proyecto. Se puede ampliar, pero ya da un criterio para evaluar los próximos cambios.

Quien lea el README tendría que poder reconocer el objetivo general y el estado actual. Un agente que lo lea va a tener contexto para interpretar los archivos. La documentación hace que el proyecto dependa menos de la memoria de quien lo creó.

5.17 Para repasar

Respondé cada pregunta con una oración completa.

  1. ¿Qué tienen en común los archivos de un proyecto?

  2. ¿Qué quiere decir “carpeta principal”?

  3. ¿Para qué sirve README.md?

  4. ¿Qué información va a comunicar AGENTS.md más adelante?

  5. ¿Qué indica la extensión .md?

  6. ¿Qué tres cosas verificaste después de crear el proyecto?

  7. ¿Para qué sirve un checkpoint?

  8. ¿Por qué una estructura correcta igual necesita una revisión metodológica?

Ver respuestas posibles

  1. Los archivos de un proyecto comparten un propósito y una organización.

  2. La carpeta principal contiene el proyecto completo y funciona como referencia para su estructura.

  3. README.md presenta el proyecto y documenta su propósito, su estado y la forma de comenzar.

  4. AGENTS.md comunicará reglas estables para los agentes que trabajen dentro del proyecto.

  5. La extensión .md indica que el archivo utiliza Markdown.

  6. Verifiqué la ubicación, la estructura y el contenido.

  7. Un checkpoint conserva una etapa recuperable y permite comparar el trabajo con una versión conocida.

  8. La estructura organiza la implementación, mientras que la revisión metodológica evalúa las decisiones de investigación representadas por esa implementación.

5.18 Errores frecuentes

5.18.1 Un .txt de más

Algunos editores agregan .txt sin avisar. Activá la visualización de extensiones y comprobá que el nombre sea README.md y no README.md.txt.

5.18.2 Una carpeta dentro de otra con el mismo nombre

Revisá la ruta completa. Lo que buscamos es una carpeta principal con el archivo directamente adentro.

mi-primer-estudio/
    README.md

5.18.3 Copias sueltas que se confunden con el proyecto

No crees varias carpetas mi-primer-estudio en distintos lugares. Si hay más de una copia, anotá cuál es la actual y cuál es un respaldo.

5.18.4 Un README demasiado general

Escribí qué se va a poder hacer con el proyecto y en qué estado está. Las frases concretas ayudan a decidir si un cambio va con el objetivo o no.

5.18.5 Querer armar toda la estructura de entrada

Cada archivo aparece cuando podés explicar para qué está. Con la estructura inicial ves todo el proyecto de un vistazo y te resulta más fácil verificarlo.

5.18.6 Trabajar sobre el checkpoint

Hacé las actividades dentro de mi-primer-estudio. proyectos\01-inicial es para comparar o para copiar una base nueva.

5.19 En síntesis

Un proyecto junta archivos y carpetas que comparten un propósito. La carpeta principal marca los límites del trabajo y es la referencia de las rutas relativas.

Los archivos pueden documentar, contener instrucciones, aportar materiales, registrar datos o configurar herramientas. La estructura crece cuando el proyecto necesita algo nuevo.

README.md presenta el proyecto con texto en Markdown, y más adelante AGENTS.md les va a dar reglas estables a los agentes.

El proyecto inicial tiene solo README.md. Con Get-Location verificamos la ubicación, con dir la estructura y leyendo el archivo, el contenido.

Un checkpoint guarda una etapa a la que podemos volver. La primera referencia del curso está en proyectos\01-inicial.

La organización técnica nos ayuda a implementar y revisar el estudio, pero son las decisiones metodológicas las que definen qué tiene que representar.

5.20 Desafío

Pedile a otra persona que revise mi-primer-estudio sin contarle antes cómo lo armaste.

  1. Tiene que encontrar la carpeta a partir de la ubicación que le digas.

  2. Tiene que identificar el propósito leyendo README.md.

  3. Tiene que describir en qué estado está el proyecto.

  4. Tiene que decir cuál es el próximo paso.

  5. Tiene que confirmar que el proyecto todavía no recolecta datos.

Anotá las preguntas que la documentación no le haya respondido. Después agregá al README una oración que resuelva esa duda y repetí la revisión.

Con este proyecto cerramos la Parte I. En la Parte II vemos cómo trabaja un agente de IA sobre una carpeta, qué puede hacer y qué decisiones tiene que conservar el investigador.
