4  Programas, procesos y errores

4.1 Objetivos

Al terminar este capítulo vas a poder

  1. distinguir la instalación, el inicio, la ejecución y el cierre de un programa;

  2. explicar qué es un proceso;

  3. observar un proceso con el Administrador de tareas;

  4. darte cuenta de cuándo PowerShell está ejecutando una instrucción;

  5. interrumpir una ejecución desde la terminal;

  6. sacar información útil de un mensaje de error;

  7. diferenciar que algo funcione técnicamente de que sea correcto desde el punto de vista metodológico.

4.2 Para empezar, una aplicación que no responde

Imaginá que abrís un programa para escribir las instrucciones de un estudio. Aparece la ventana y empezás a trabajar. En un momento intentás abrir un archivo grande y el programa deja de responder durante varios segundos.

La ventana sigue ahí y el puntero quizás muestra que algo está cargando. El sistema operativo todavía tiene que decidir cómo repartir sus recursos, y vos tenés que decidir si esperás, si intentás cerrar la aplicación o si buscás más información.

En esa situación pasan varias cosas distintas. Primero el programa tuvo que estar disponible en la computadora. Después el sistema operativo lo inició. Mientras trabajabas hubo un proceso activo. Y al final el programa respondió, terminó o se encontró con un problema.

Entender esa secuencia te va a servir cuando más adelante ejecutes un estudio, una herramienta o un agente desde la terminal.

Idea clave

Un programa empieza a ejecutarse, usa recursos mientras trabaja y en algún momento termina. Durante ese tiempo el sistema operativo mantiene uno o más procesos dedicados a esa tarea.

4.3 Instalar

Instalar un programa es incorporar a la computadora los archivos y la configuración que necesita para funcionar. Una instalación puede copiar archivos, crear accesos directos, registrar componentes y ajustar opciones del sistema operativo.

En general se instala una vez y después el programa se abre muchas veces. Cuando instalás un navegador, sus archivos quedan guardados aunque apagues la computadora, y cada vez que lo abrís empieza una ejecución nueva.

Algunos programas se usan sin un instalador tradicional, porque vienen con el sistema o funcionan desde una carpeta. Eso depende de cómo se distribuyen. En cualquier caso, el sistema necesita encontrar instrucciones que pueda ejecutar.

Instalar deja cambios más o menos duraderos, mientras que iniciar produce una actividad temporal. Vamos a volver a esta diferencia cuando aparezcan herramientas como Node.js, que primero se instalan y después se ejecutan cada vez que una actividad las necesita.

4.4 Iniciar

Un programa se puede iniciar desde el menú Inicio, con un ícono, abriendo un archivo asociado o desde la terminal.

Cuando hacés doble clic sobre un archivo .txt, el sistema operativo busca qué aplicación está asociada a ese tipo de archivo, la inicia y le dice qué archivo tiene que abrir.

También podés iniciar una aplicación por su nombre desde PowerShell. Este ejemplo le pide a Windows que abra el Bloc de notas.

notepad

El nombre disponible puede variar según el sistema. Si ese comando no te funciona, podés hacer las actividades del capítulo desde el menú Inicio.

Detrás de lo que vemos cuando arranca una aplicación hay varias operaciones. El sistema encuentra sus archivos, reserva memoria de trabajo, crea un proceso y prepara la interfaz. Una aplicación compleja puede crear varios procesos para separar tareas.

4.5 Ejecutar

En el primer capítulo dijimos que ejecutar es poner en funcionamiento las instrucciones de un programa. La ejecución empieza cuando el sistema arranca esas instrucciones y sigue mientras el programa hace su trabajo.

Mientras se ejecuta, un programa puede recibir entradas, leer archivos, transformar datos y producir salidas. Algunas ejecuciones siguen activas hasta que la persona cierra una ventana. Otras hacen una tarea corta y terminan solas.

Pensá en la calculadora, que queda abierta mientras le das números y operaciones. Ahora pensá en Get-Location, que muestra una ruta y termina casi al instante.

Las dos son ejecuciones. Lo que cambia es cuánto duran y cómo interactuamos con ellas.

4.6 Los procesos

Un proceso es un programa que se está ejecutando. Incluye las instrucciones activas, la memoria que usan y otros recursos que el sistema operativo tiene que administrar. Es la definición básica que usa la documentación técnica de Windows.

Podemos pensar el programa como algo guardado que está disponible para usarse. El proceso aparece cuando esas instrucciones se ponen en marcha, y cuando la ejecución termina el sistema libera los recursos que usaba.

Una aplicación puede usar un solo proceso o varios. Los navegadores, por ejemplo, suelen repartir su trabajo, y por eso el Administrador de tareas a veces muestra varias filas para una misma aplicación.

Cada proceso recibe un número que lo identifica durante esa ejecución. Se llama identificador de proceso y también vas a ver la sigla PID, del inglés process identifier. La próxima vez que abras el programa ese número puede ser otro.

Para este curso quedate con esta idea. Mientras una herramienta trabaja hay una ejecución activa, y esa ejecución puede producir salidas, esperar entradas, terminar o encontrarse con un error.

4.7 El Administrador de tareas

El Administrador de tareas es una herramienta de Windows que muestra las aplicaciones y los procesos activos, y cuánto procesador y memoria usan. Microsoft describe estas funciones en su guía sobre las herramientas de configuración de Windows.

Lo podés abrir desde el menú Inicio o con la combinación de teclas Ctrl + Shift + Esc.

La pestaña o sección Procesos muestra las aplicaciones activas. La organización puede cambiar según la versión de Windows, así que buscá el nombre de la aplicación que te interesa.

Las columnas se actualizan todo el tiempo. El uso de procesador puede subir mientras la aplicación hace algo, y el uso de memoria muestra una parte de los recursos que el proceso tiene reservados.

Finalizá una tarea solo si sabés qué va a pasar

El Administrador de tareas permite forzar el cierre de un programa, y eso puede hacer que se pierdan cambios sin guardar. Primero intentá guardar y cerrar la aplicación de la forma habitual.

4.8 Cuando el indicador no vuelve

En el capítulo anterior vimos que el indicador aparece cuando PowerShell espera una instrucción.

PS C:\Users\Ana>

Si un comando sigue activo, el indicador puede tardar en volver, porque PowerShell está esperando que la operación termine.

Con el comando Start-Sleep podemos ver esto sin tocar ningún archivo. Lo que hace es dejar la sesión en pausa durante el tiempo que le digamos, como explica su referencia oficial.

Start-Sleep -Seconds 5

La parte -Seconds se llama parámetro. Un parámetro le dice al comando cómo interpretar el valor que viene después. Acá el número 5 significa cinco segundos.

Después de apretar Enter, el indicador desaparece durante cinco segundos y vuelve cuando el comando termina.

Esto es una pista útil. Si el indicador no está, es probable que el comando siga ejecutándose, así que conviene esperar o fijarse qué está pasando antes de escribir otra cosa.

4.9 Interrumpir con Ctrl + C

A veces una ejecución tarda más de lo que esperábamos. En PowerShell, la combinación Ctrl + C pide que se interrumpa la operación activa. Según la documentación de PowerShell, esa combinación detiene lo que se está ejecutando en ese momento.

Probalo con un comando que espera treinta segundos.

Start-Sleep -Seconds 30

Después de unos segundos, mantené apretada la tecla Ctrl y apretá C. El indicador tendría que volver antes de que pasen los treinta segundos.

La interrupción actúa sobre lo que se está ejecutando en esa terminal, pero lo que ya se hizo antes puede quedar. Si un programa ya guardó un archivo, ese archivo sigue ahí aunque detengas el resto de la tarea.

Por eso interrumpir no es lo mismo que deshacer. Interrumpir frena lo que faltaba. Para recuperar lo anterior hay que revisar qué llegó a pasar.

4.10 Las formas de terminar

Una ejecución puede terminar porque completó su tarea, como Get-Location cuando muestra la ruta. Una aplicación con ventana termina cuando elegís Cerrar.

También puede terminar porque alguien pide que se interrumpa, que es lo que hace Ctrl + C con muchas tareas de la terminal.

Y puede frenarse porque encontró algo que le impide seguir. En ese caso el programa suele mostrar un mensaje de error.

Cuando cerramos un programa de la forma habitual, le damos la oportunidad de guardar información y liberar recursos. El cierre forzado le quita esa oportunidad. Por eso conviene dejarlo para cuando la aplicación dejó de responder y el trabajo ya está guardado.

4.11 Los errores

Un error aparece cuando una instrucción se encuentra con algo que le impide hacer lo que se esperaba. Puede faltar un archivo, la ruta puede estar mal, el comando puede tener un nombre que no existe o puede faltar un permiso.

El mensaje de error también es una salida del programa, y su función es describir el problema. PowerShell guarda información sobre los comandos que fallan y muestra distintos detalles según el tipo de error. En la documentación sobre el manejo de errores se explica que algunos problemas frenan una operación y otros dejan seguir con las tareas siguientes.

En las primeras prácticas alcanza con buscar cuatro cosas.

  1. Qué instrucción produjo el mensaje.

  2. Qué archivo, carpeta o comando se menciona.

  3. Alguna expresión que describa el problema, como “ruta inexistente”, “término desconocido” o “acceso denegado”.

  4. Qué pasó después del mensaje.

En PowerShell los errores suelen aparecer en rojo, pero el color depende de la configuración. Lo que dice el mensaje es más confiable que cómo se ve.

4.12 Cómo leer un mensaje largo

Los mensajes técnicos pueden tener muchas líneas, y algunas están pensadas para gente con experiencia en programación. Podés empezar con una lectura acotada, en cinco pasos.

4.12.1 Primero, qué esperabas

Escribí una oración concreta, como “Esperaba entrar en la carpeta materiales”. Con esa oración podés comparar lo que querías hacer con lo que pasó.

4.12.2 Segundo, qué instrucción falló

Copiá o leé el comando exacto, porque un solo carácter distinto puede cambiar su significado.

cd materialess

4.12.3 Tercero, qué objeto se menciona

El mensaje puede repetir materialess o mostrar una ruta completa. Eso te dice qué intentó encontrar PowerShell.

4.12.4 Cuarto, el contexto

Ejecutá Get-Location para confirmar la carpeta actual y dir para ver qué nombres hay disponibles.

4.12.5 Quinto, corregir una cosa y volver a probar

Si en la lista aparece materiales, corregí el nombre y ejecutá el comando otra vez.

cd materiales

Si cambiás una sola cosa por vez, sabés qué corrección produjo el resultado.

Guardá el mensaje exacto cuando pidas ayuda

Copiá el comando y el mensaje completo, y anotá también la carpeta actual y lo que esperabas que pasara. Con esa información otra persona, o un agente, puede analizar la situación con mucha más precisión.

4.13 Salidas, advertencias y errores

Una salida informa un resultado normal. Cuando Get-Location muestra una ruta, está haciendo exactamente lo que tiene que hacer.

Una advertencia avisa sobre algo que merece atención. El programa puede seguir, aunque haya un riesgo o una configuración poco recomendable.

Un error avisa que alguna operación tuvo un problema. El alcance varía. Puede fallar una acción puntual y la sesión seguir, o puede terminar todo el programa.

Por eso, cuando aparece texto después de un comando, hay que leerlo. La cantidad de líneas y el color dan pistas, pero son las palabras y el resultado final los que permiten entender qué pasó.

Algunos programas de la terminal devuelven un código de salida cuando terminan. En general 0 quiere decir que todo salió bien y cualquier otro valor indica un problema. Vas a ver estos códigos más adelante, cuando ejecutes herramientas del proyecto. Por ahora alcanza con saber que un programa puede comunicar cómo terminó mediante un número.

4.14 Actividad

Actividad guiada

En la primera parte vas a observar un proceso usando una aplicación conocida.

  1. Abrí el Bloc de notas desde el menú Inicio.

  2. Escribí una oración y guardala en practica_archivos\instrucciones con el nombre observacion_proceso.txt.

  3. Abrí el Administrador de tareas con Ctrl + Shift + Esc.

  4. Buscá el Bloc de notas en la sección Procesos.

  5. Mirá el nombre de la aplicación y la información sobre sus recursos.

  6. Cerrá el Bloc de notas con su botón habitual.

  7. Volvé al Administrador de tareas y fijate qué cambió.

En la segunda parte vas a observar una ejecución dentro de PowerShell.

  1. Abrí PowerShell.

  2. Ejecutá Start-Sleep -Seconds 5 y fijate cuándo vuelve el indicador.

  3. Ejecutá Start-Sleep -Seconds 30.

  4. Esperá unos segundos y apretá Ctrl + C.

  5. Comprobá que el indicador volvió antes de los treinta segundos.

En la tercera parte vas a provocar un error a propósito y a corregirlo.

  1. Entrá en practica_archivos como lo hiciste en el capítulo anterior.

  2. Ejecutá cd materialess. El nombre tiene una letra de más a propósito.

  3. Leé el mensaje y buscá qué nombre intentó encontrar PowerShell.

  4. Ejecutá Get-Location y comprobá que seguís en la misma carpeta.

  5. Ejecutá dir y buscá el nombre correcto.

  6. Ejecutá cd materiales.

  7. Ejecutá Get-Location y comprobá que la corrección funcionó.

4.15 Qué pasó en la actividad

El Bloc de notas ya estaba instalado antes de empezar. Cuando lo abriste, Windows inició una ejecución y creó un proceso, que pudiste ver en el Administrador de tareas. Al cerrar la aplicación, la ejecución terminó y la lista de procesos se actualizó.

Start-Sleep -Seconds 5 dejó la sesión ocupada durante cinco segundos, y la ausencia del indicador te mostró que PowerShell estaba esperando. El segundo comando lo cortaste con Ctrl + C y la sesión volvió a quedar disponible.

Con cd materialess pediste una carpeta que no existía en la ubicación actual. PowerShell avisó del problema y la sesión siguió abierta. Get-Location y dir te dieron el contexto para corregir el nombre, y la segunda vez funcionó.

4.16 Por qué nos importa en Psicología

Un estudio puede abrirse, mostrar pantallas y guardar datos sin un solo mensaje de error. Eso es evidencia técnica, porque nos dice que ciertas instrucciones se pudieron ejecutar.

La revisión metodológica hace otras preguntas. Se fija si los estímulos corresponden al constructo, si la asignación a condiciones respeta el diseño, si las respuestas quedan registradas con el significado que queríamos y si el procedimiento cumple con las decisiones éticas.

Supongamos que una tarea tiene que mostrar una palabra durante 500 milisegundos. El programa podría ejecutarse sin errores y mostrarla durante 5000 milisegundos. La aplicación funcionaría, pero la duración no sería la que decidimos.

Por eso verificamos en dos niveles.

  1. La verificación técnica comprueba que el programa arranca, responde y produce archivos que se pueden usar.

  2. La verificación metodológica comprueba que el procedimiento hace lo que decidimos en la investigación.

Un mensaje de error ayuda a encontrar un problema técnico. Que no aparezca ninguno no alcanza, y todavía hay que revisar el comportamiento y los datos.

4.17 Para repasar

Respondé cada pregunta con una oración completa.

  1. ¿Qué diferencia hay entre instalar e iniciar un programa?

  2. ¿Qué es un proceso?

  3. ¿Qué herramienta de Windows te permite ver los procesos activos?

  4. ¿Qué indica que el indicador de PowerShell desaparezca por un rato?

  5. ¿Qué pide la combinación Ctrl + C durante una ejecución en la terminal?

  6. ¿Qué dos comandos te ayudan a entender el contexto de un error de ruta?

  7. ¿Por qué un programa que termina sin errores igual necesita una revisión metodológica?

Ver respuestas posibles

  1. Instalar prepara archivos y configuraciones para usos posteriores, mientras que iniciar comienza una ejecución concreta.

  2. Un proceso representa un programa que se encuentra en ejecución y utiliza recursos del sistema.

  3. El Administrador de tareas permite observar procesos activos.

  4. La ausencia temporal del indicador puede señalar que PowerShell espera que termine una operación.

  5. Ctrl + C solicita la interrupción de la ejecución activa.

  6. Get-Location permite revisar la ubicación y dir permite observar los nombres disponibles.

  7. La ejecución técnica no demuestra que el procedimiento represente correctamente las decisiones metodológicas.

4.18 Errores frecuentes

4.18.1 Confundir instalar con ejecutar

La instalación prepara el programa y deja cambios duraderos. Cada ejecución usa esa instalación para hacer una tarea concreta.

4.18.2 Preocuparse por ver varios procesos

El Administrador de tareas puede mostrar varias filas para un navegador u otra aplicación compleja. Así están diseñadas y no es señal de que algo ande mal.

4.18.3 Forzar el cierre con trabajo sin guardar

El cierre habitual suele preguntarte si querés guardar, y el cierre forzado se saltea esa pregunta. Si el archivo tiene cambios importantes, guardalo antes de finalizar la tarea.

4.18.4 Pensar que toda espera es un problema

Hay operaciones que necesitan tiempo para leer archivos, calcular resultados o poner en marcha un servicio. Mirá la salida y la actividad antes de concluir que el programa se colgó.

4.18.5 Asustarse con un mensaje largo

Empezá por la instrucción, el objeto que se menciona y la primera descripción que entiendas. Guardá el mensaje completo por si hace falta revisarlo después.

4.18.6 Corregir varias cosas a la vez

Si cambiás muchas cosas juntas, no sabés cuál resolvió el problema. Aplicá una corrección, volvé a probar y recién después seguí.

4.19 En síntesis

Instalar prepara un programa para usarlo después, e iniciar pone en marcha una ejecución concreta. Un proceso es un programa que está funcionando y que usa recursos administrados por el sistema operativo.

Con el Administrador de tareas podemos ver los procesos. En la terminal, PowerShell muestra el indicador cuando espera una instrucción, y mientras un comando sigue activo el indicador puede no aparecer. Con Ctrl + C pedimos que se interrumpa.

Un error nos cuenta que hubo un problema. La instrucción, la ubicación, el objeto mencionado y la descripción nos dan pistas para corregirlo, y la prueba posterior confirma si lo logramos.

Que algo se ejecute bien es evidencia técnica. En investigación también tenemos que comprobar que esas instrucciones hacen lo que decidimos metodológicamente.

4.20 Desafío

Elegí una aplicación que uses seguido, como un navegador, un reproductor o un editor de texto.

  1. Escribí una oración que explique cómo la iniciás.

  2. Escribí otra que nombre una entrada que recibe mientras se ejecuta.

  3. Escribí una más que nombre una salida que produce.

  4. Abrí el Administrador de tareas y contá cómo reconociste su proceso.

  5. Cerrá la aplicación de la forma habitual y describí qué cambió.

  6. Imaginá un problema técnico que podría aparecer mientras la usás.

  7. Escribí qué información necesitarías para investigar ese problema.
