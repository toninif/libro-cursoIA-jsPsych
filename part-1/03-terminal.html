3  La terminal

3.1 Objetivos

Al terminar este capítulo vas a poder

  1. explicar qué es una terminal y qué hace PowerShell;

  2. reconocer en qué carpeta está trabajando la terminal;

  3. ver el contenido de una carpeta y moverte entre carpetas;

  4. crear una carpeta escribiendo una instrucción;

  5. comprobar si cada instrucción hizo lo que esperabas;

  6. entender dos mensajes frecuentes sin abandonar la actividad.

3.2 Para empezar, una carpeta conocida

En el capítulo anterior creaste una carpeta llamada practica_archivos. Entraste con el Explorador de archivos, miraste qué tenía y abriste sus carpetas internas. Todo lo hiciste con clics sobre íconos, nombres y botones.

Ahora imaginá que tenés que explicarle a otra persona cómo llegar hasta la carpeta materiales. Podrías describirle una secuencia de clics, o podrías escribirle una lista de instrucciones que nombren cada acción y cada lugar.

La terminal trabaja de esa segunda forma. Vos escribís una instrucción, un programa la interpreta, la computadora hace algo y te muestra el resultado.

En este capítulo vamos a recorrer la misma organización que ya armaste. Usamos pocas instrucciones y cada una tiene un propósito concreto y una forma de comprobar que funcionó.

Idea clave

El Explorador de archivos y la terminal trabajan sobre las mismas carpetas. Lo que cambia es la forma de pedir las cosas. El Explorador recibe clics y la terminal recibe texto.

3.3 Qué es una terminal

Una terminal es un programa en el que escribimos instrucciones y leemos sus resultados. Suele ser una ventana con texto sobre un fondo liso, con una línea preparada para recibir lo que escribas.

Windows trae varias herramientas para esto. En el libro usamos Windows Terminal cuando está disponible. Es una aplicación que puede alojar distintos intérpretes de comandos, como explica Microsoft en su documentación de Windows Terminal.

Un intérprete de comandos es un programa que lee instrucciones escritas y le pide al sistema operativo que las ejecute. En Windows vamos a trabajar con PowerShell, que es uno de esos intérpretes.

Separar las dos cosas ayuda a entender lo que ves en pantalla.

  1. Windows Terminal pone la ventana y organiza las sesiones.

  2. PowerShell interpreta lo que escribís dentro de esa ventana.

Puede que en tu computadora encuentres una aplicación llamada PowerShell y no tengas Windows Terminal instalada. No hay problema, porque esa aplicación también sirve para todo lo que hacemos en este capítulo.

3.4 El indicador

Cuando abrís PowerShell vas a ver una línea parecida a esta.

PS C:\Users\Ana>

Esa línea se llama indicador. En la documentación técnica también vas a encontrar la palabra inglesa prompt.

El indicador te da dos datos. Las letras PS avisan que estás usando PowerShell y el texto C:\Users\Ana muestra dónde estás parado. El signo > marca el lugar desde donde podés escribir.

Ese lugar donde estás parado se llama carpeta de trabajo actual. PowerShell interpreta muchas instrucciones a partir de ella, así que conviene saber cuál es antes de cambiar nada.

Cuando el libro muestre una instrucción, escribí solo lo que está dentro del bloque de código. El indicador ya aparece en tu terminal. Por ejemplo, si ves esto

Get-Location

no hace falta que escribas PS C:\Users\Ana> adelante.

Revisá la carpeta actual antes de modificar archivos

Una instrucción puede funcionar perfecto en la carpeta equivocada. Antes de crear o cambiar algo, usá Get-Location y fijate qué ruta muestra PowerShell.

3.5 Los comandos

Un comando es una instrucción escrita que pide una acción. PowerShell tiene comandos para consultar dónde estamos, movernos entre carpetas y muchas otras tareas.

El comando Get-Location pide la ubicación actual.

Get-Location

Después de escribirlo apretá Enter. PowerShell ejecuta el comando y muestra una ruta. Si querés más detalle, Microsoft lo describe en la referencia oficial del comando.

La salida se ve más o menos así.

Path
----
C:\Users\Ana

Path quiere decir ruta, y la última línea es la carpeta de trabajo actual.

Apretar Enter tiene una función precisa. Le avisa a PowerShell que terminaste de escribir y que ya puede interpretar la instrucción.

3.6 Ver el contenido con dir

El comando dir pide la lista de lo que hay en la carpeta actual.

dir

La salida puede incluir nombres de carpetas y de archivos, fechas y tamaños. Cuánta información aparece depende del contenido y de la versión de PowerShell.

dir es un nombre corto que PowerShell acepta para el comando Get-ChildItem. A un nombre alternativo de este tipo se lo llama alias, y sirve para escribir menos. Microsoft documenta esta equivalencia en su explicación sobre los alias de PowerShell.

Por ahora alcanza con recordar que dir te muestra qué hay en la carpeta actual.

Esa lista también sirve para verificar. Si esperabas encontrar materiales y el nombre aparece, confirmaste que la carpeta está ahí. Si no aparece, hay que revisar dónde estás o cómo están organizados los archivos.

3.7 Moverse con cd

El comando cd sirve para entrar en otra carpeta. Necesita que le digas el nombre o la ruta del destino.

cd materiales

Acá materiales es un argumento, o sea, la información que el comando necesita para hacer su trabajo. En este caso le indica adónde ir.

Después de ejecutarlo vas a ver que el indicador cambia. También podés ejecutar Get-Location para confirmar la nueva ubicación.

Get-Location

PowerShell acepta cd como alias de Set-Location. En la referencia de Set-Location se explica que ese comando fija la ubicación de trabajo actual.

3.7.1 Volver con cd ..

Mirá esta instrucción.

cd ..

Los dos puntos seguidos representan la carpeta que contiene a la actual. Si estás dentro de practica_archivos\materiales, esta instrucción te lleva a practica_archivos.

Para comprobar el cambio usá Get-Location, y si querés ver qué hay en el lugar al que llegaste, ejecutá dir.

3.7.2 Rutas con espacios

Una ruta puede tener espacios, y PowerShell necesita reconocerla como una sola cosa. Para eso están las comillas.

cd "C:\Users\Ana\Documents\Curso Psicología"

La ruta del ejemplo cambia de una computadora a otra, así que no la copies como si fuera la tuya. Usá la ruta de tu carpeta.

Hay una forma de escribir menos. Abrí la carpeta en el Explorador de archivos, hacé clic en la barra de direcciones y copiá la ruta completa. Después escribí cd, dejá un espacio, pegá la ruta entre comillas y apretá Enter.

cd "PEGÁ AQUÍ LA RUTA DE TU CARPETA"

Las comillas funcionan aunque la ruta no tenga espacios. Por eso, en las primeras actividades, conviene usarlas siempre.

3.7.3 Completar con Tab

PowerShell puede completar nombres que ya existen. Escribí las primeras letras de una carpeta y apretá la tecla Tab. Si hay una coincidencia, PowerShell completa el nombre, y si hay varias, podés seguir apretando Tab para recorrerlas.

Esto evita errores de tipeo y ayuda mucho con los nombres largos. Igual, mirá cómo quedó la instrucción antes de apretar Enter.

3.8 Crear una carpeta con mkdir

El comando mkdir crea una carpeta en la ubicación actual. El nombre va después del comando.

mkdir practica_terminal

En esta instrucción practica_terminal es el argumento, y PowerShell lo usa como nombre de la carpeta nueva.

Para verificar hace falta un paso más.

dir

La carpeta practica_terminal tendría que aparecer en la lista. También podés abrir el Explorador de archivos y ver el cambio desde ahí.

PowerShell acepta mkdir como forma corta de crear una carpeta. La documentación de las funciones incorporadas describe esta equivalencia.

3.9 Limpiar la pantalla con cls

Después de un rato la ventana se llena de líneas. El comando cls borra el texto que se ve.

cls

Los archivos, las carpetas y la ubicación actual quedan como estaban, y la sesión sigue abierta. Lo único que cambia es lo que ves en pantalla. Microsoft lo explica en la referencia de Clear-Host, que es el comando que está detrás de cls.

Si ejecutás Get-Location después de cls, vas a ver que seguís en la misma carpeta.

3.10 Actividad

Actividad guiada

Necesitás la carpeta practica_archivos del capítulo anterior. Si no la tenés, creala con el Explorador de archivos y agregale las carpetas instrucciones, materiales y datos.

  1. Abrí Windows Terminal o PowerShell desde el menú Inicio.

  2. Escribí Get-Location y apretá Enter. Leé la ruta que aparece.

  3. Abrí practica_archivos en el Explorador de archivos y copiá su ruta desde la barra de direcciones.

  4. Volvé a PowerShell. Escribí cd, dejá un espacio y pegá la ruta entre comillas. Te va a quedar algo parecido a cd "C:\Users\Ana\Documents\practica_archivos".

  5. Ejecutá Get-Location y comprobá que la última parte de la ruta sea practica_archivos.

  6. Ejecutá dir y comprobá que aparezcan instrucciones, materiales y datos.

  7. Ejecutá cd materiales para entrar en esa carpeta.

  8. Ejecutá dir. Si hiciste la actividad anterior, tendría que aparecer ejemplo.txt.

  9. Ejecutá cd .. para volver a practica_archivos.

  10. Ejecutá mkdir practica_terminal para crear una carpeta.

  11. Ejecutá dir y comprobá que practica_terminal esté en la lista.

  12. Ejecutá cd practica_terminal y después Get-Location. Revisá la ruta.

  13. Ejecutá cd .. para volver a practica_archivos.

  14. Ejecutá cls para limpiar la pantalla.

  15. Ejecutá Get-Location una vez más y comprobá que limpiar la pantalla no cambió la ubicación.

3.11 Qué pasó en la actividad

PowerShell arrancó en una carpeta que depende de cómo está configurada tu computadora, y Get-Location te mostró cuál era.

El primer cd cambió la carpeta de trabajo actual usando una ruta completa como argumento. Después dir mostró lo que había en practica_archivos.

Con cd materiales PowerShell interpretó una ruta relativa, es decir, buscó materiales dentro de la carpeta en la que estabas. Con cd .. volviste a la carpeta que contiene a materiales.

mkdir practica_terminal sí modificó algo guardado en la computadora, porque creó una carpeta dentro de practica_archivos. Con dir comprobaste el resultado.

cls solo cambió lo que se veía en la terminal, y Get-Location confirmó que la ubicación seguía igual.

En la actividad repetiste un ciclo corto que vamos a usar muchísimas veces.

observar la ubicación
          ↓
escribir una instrucción
          ↓
leer el resultado
          ↓
comprobar el cambio

3.12 Por qué nos importa en Psicología

Un proyecto reúne los archivos y carpetas de un mismo trabajo. Más adelante tu proyecto va a tener las instrucciones y los materiales de un estudio psicológico.

Muchas herramientas trabajan sobre la carpeta actual. Un agente de IA que corre desde la terminal también necesita saber qué proyecto tiene que mirar. Si lo abrís desde otro lugar, puede encontrar archivos que no son los que pensabas o no encontrar lo que necesita.

Por eso, antes de pedir un cambio, conviene hacer tres comprobaciones.

  1. Get-Location tiene que mostrar la carpeta del proyecto correcto.

  2. dir tiene que mostrar los archivos que esperás encontrar.

  3. La instrucción para el agente tiene que decir qué cambiar y hasta dónde.

Esto también es parte del trabajo de investigación. Si un cambio se aplica a la versión equivocada, el procedimiento que revisaste y el que finalmente se ejecuta pueden terminar siendo distintos.

La ubicación también se verifica

Un comando puede estar bien escrito y actuar sobre una carpeta que no esperabas. Revisar la ruta te confirma sobre qué actuó realmente.

3.13 Dos mensajes frecuentes

Cuando PowerShell encuentra un problema, muestra un texto que dice qué instrucción recibió y qué parte falló. En el próximo capítulo vemos cómo leer mensajes de error con más calma. Por ahora vamos a reconocer dos situaciones que aparecen seguido.

3.13.1 No encuentra una ruta

Este mensaje aparece cuando la ubicación que pediste no coincide con ninguna carpeta a la que se pueda llegar desde donde estás. Puede haber un error de tipeo, faltar una parte de la ruta o faltar una comilla.

Probá con estas comprobaciones.

  1. Ejecutá Get-Location para saber desde dónde partís.

  2. Ejecutá dir para ver qué nombres hay disponibles.

  3. Compará lo que escribiste con lo que aparece en la lista.

  4. Poné comillas si la ruta tiene espacios.

  5. Usá Tab para completar un nombre que existe.

Después corregí la instrucción y volvé a ejecutarla.

3.13.2 No reconoce un término

Este mensaje suele aparecer cuando el nombre del comando está mal escrito. Compará letra por letra con el ejemplo y fijate que haya un espacio entre el comando y su argumento.

cd materiales

En este ejemplo cd es el comando y materiales es el argumento. El espacio es lo que permite distinguirlos.

Un mensaje de error también es una salida. Te dice que PowerShell pudo leer la instrucción pero tuvo un problema al interpretarla o al ejecutarla.

3.14 Algunas precauciones

La terminal hace cambios rápido, y eso pide revisar con atención.

  1. Comprobá la carpeta actual antes de crear, mover o eliminar cosas.

  2. Ejecutá comandos cuyo propósito puedas explicar con tus palabras.

  3. Leé cualquier instrucción copiada antes de apretar Enter.

  4. Verificá el resultado después de cada cambio.

  5. No uses permisos de administrador para las actividades del libro, salvo que más adelante una instrucción explique por qué hace falta.

  6. Si trabajás con archivos importantes, guardá copias que puedas recuperar.

En este capítulo no usamos comandos para eliminar. Primero conviene que te acostumbres a controlar dónde estás y a verificar los resultados.

  4. ¿Qué comando muestra el contenido de esa carpeta?

  5. ¿Qué función cumple materiales en la instrucción cd materiales?

  6. ¿Qué representa .. en la instrucción cd ..?

  7. ¿Cómo comprobarías que mkdir practica_terminal hizo lo que esperabas?

  8. ¿Qué les pasa a los archivos cuando ejecutás cls?

Ver respuestas posibles

  1. PowerShell interpreta los comandos de este capítulo.

  2. El indicador muestra que PowerShell espera una instrucción y suele incluir la carpeta actual.

  3. Get-Location muestra la carpeta de trabajo actual.

  4. dir muestra el contenido de la carpeta actual.

  5. materiales funciona como argumento e indica la carpeta de destino.

  6. Los dos puntos representan la carpeta que contiene la ubicación actual.

  7. Ejecutaría dir y comprobaría que practica_terminal aparezca en la lista.

  8. Los archivos permanecen sin cambios cuando ejecuto cls.

3.16 Errores frecuentes

3.16.1 Confundir el indicador con el comando

El indicador avisa que PowerShell espera una instrucción. El comando es lo que escribís después del signo >.

3.16.2 Olvidar en qué carpeta estás

mkdir practica_terminal crea la carpeta dentro de la ubicación actual. El mismo comando, ejecutado en otro lugar, crea otra carpeta con el mismo nombre en otra parte.

3.16.3 Pensar que el Explorador y la terminal ven cosas distintas

Una carpeta creada con mkdir aparece en el Explorador, y una creada con el Explorador aparece cuando ejecutás dir. Las dos interfaces trabajan sobre los mismos archivos.

3.16.4 Creer que cls borra el trabajo

cls limpia el texto de la ventana. Las carpetas que creaste y la ubicación actual siguen igual.

3.16.5 Querer memorizar todos los comandos

No hace falta. En una tarea real podés consultar la documentación y los ejemplos. En esta etapa lo importante es entender qué hace cada acción, reconocer sus argumentos y saber cómo verificar el resultado.

3.17 En síntesis

La terminal nos permite darle instrucciones a la computadora por escrito. Windows Terminal es la aplicación que aloja las sesiones y PowerShell es el que interpreta los comandos de este capítulo.

El indicador avisa que PowerShell espera una instrucción y suele mostrar la carpeta actual. Con Get-Location confirmamos esa ubicación y con dir vemos su contenido. cd nos lleva a otra carpeta y cd .. nos devuelve a la que contiene la actual. mkdir crea una carpeta y cls limpia la pantalla sin tocar los archivos.

Cada instrucción se verifica. La ruta nos dice sobre qué actuamos, la salida nos muestra qué pasó y el Explorador de archivos nos da otra forma de mirar los cambios.

Todo esto prepara el trabajo con proyectos y agentes, porque antes de modificar un estudio vamos a tener que confirmar qué carpeta tiene la versión correcta.

Abrí PowerShell y llegá hasta practica_archivos. Después hacé lo siguiente.

  1. Ejecutá un comando que muestre la ubicación actual.

  2. Ejecutá un comando que muestre el contenido de la carpeta.

  3. Creá una carpeta llamada verificacion.

  4. Entrá en verificacion.

  5. Comprobá la nueva ubicación.

  6. Volvé a practica_archivos.

  7. Escribí seis oraciones. En cada una contá qué comando usaste, qué esperabas que pasara y cómo comprobaste el resultado.
