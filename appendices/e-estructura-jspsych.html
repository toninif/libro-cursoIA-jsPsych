33  Estructura de un proyecto jsPsych

33.1 Cómo usar este apéndice

Este apéndice ofrece una vista de conjunto del proyecto que construiste durante el libro. Sirve para consultar qué hace cada archivo, dónde se define cada decisión y qué datos produce cada tipo de pantalla. Todo lo que aparece aquí se explicó antes en los capítulos, que se indican en cada sección.

33.2 Los archivos del proyecto final

La estructura del proyecto al final del libro, igual a la del checkpoint 07-estudio-completo, es esta.

mi-primer-estudio/
├── index.html
├── experiment.js
├── styles.css
├── diseno.md
├── diccionario.md
├── AGENTS.md
└── README.md

Los tres primeros archivos forman el estudio: son los que el navegador interpreta. Los cuatro restantes forman la documentación: explican el estudio a personas y agentes.

33.4 La organización de index.html

<head>
  ├── codificación (charset) y adaptación al celular (viewport)
  ├── título de la pestaña
  ├── jsPsych
  ├── un plugin por cada tipo de pantalla
  ├── extensión de DataPipe
  ├── hoja de estilos de jsPsych
  └── styles.css (después de la de jsPsych)
<body>
  └── experiment.js

Cada dirección de unpkg.com termina con una versión fija. La hoja de estilos propia se carga después de la de jsPsych, para que sus reglas tengan prioridad. experiment.js se carga al final, cuando todo lo anterior ya está disponible.

33.5 La organización de experiment.js

El archivo del estudio final tiene siempre el mismo orden. Conocerlo ayuda a ubicar un cambio.

1. Configuración de DataPipe          DATAPIPE_ID
2. Configuración de jsPsych           initJsPsych: barra de progreso, extensión, on_finish
3. Identificador de participante      randomID y addProperties
4. Definición de los ensayos          bienvenida, consentimiento, preguntas, escalas, cierre
5. Orden aleatorio de las escalas     shuffle y primera_escala
6. Línea de tiempo                    jsPsych.run([...])

Los nombres se definen antes de usarse. Por eso las escalas se definen antes de mezclarlas, y todo se define antes de jsPsych.run. La única excepción aparente es participante dentro de on_finish y de filename: esas instrucciones se ejecutan recién al final del estudio, cuando participante ya existe.

33.6 La anatomía de un ensayo

Todos los ensayos comparten una forma. Algunos parámetros son comunes a todos los plugins y otros son propios de cada uno.

const pregunta_estudiante = {
  type: jsPsychSurveyMultiChoice,          // plugin: define el tipo de pantalla
  questions: [ ... ],                      // parámetros propios del plugin
  button_label: "Continuar",
  data: { pantalla: "estudiante" },        // común: agrega columnas a los datos
  on_finish: function (data) { ... }       // común: se ejecuta al terminar el ensayo
};

Una línea de tiempo anidada tiene otra forma: un bloque con timeline y, opcionalmente, conditional_function.

const pregunta_herramientas_ia = {
  timeline: [ { ...un ensayo... } ],
  conditional_function: function () { ... }
};

33.7 Plugins usados y datos que producen

Todas las direcciones comienzan con https://unpkg.com/. La biblioteca se carga con https://unpkg.com/jspsych@8.3.0 y la extensión de DataPipe con https://unpkg.com/@jspsych/extension-pipe@0.2.0.

Además de response, cada fila incluye columnas que jsPsych agrega por su cuenta: rt, trial_type, trial_index, time_elapsed y plugin_version. Algunos plugins agregan columnas propias, como question_order en las escalas y los cuestionarios con orden aleatorio. El capítulo 15 explica cada una.

33.8 Cómo creció el proyecto

El proyecto creció de a un archivo por vez, cuando cada uno se volvió necesario. Los checkpoints del libro conservan cada etapa.

Cada checkpoint funciona por separado. Si tu versión deja de funcionar, podés copiar los archivos del checkpoint de la etapa en la que estás y continuar desde allí.

33.9 Cuando el proyecto crece más

El estudio del libro cabe cómodamente en un solo archivo experiment.js. En estudios con muchas escalas o muchas pantallas, ese archivo puede volverse difícil de leer. Una organización habitual en ese caso separa el código en varios archivos dentro de una carpeta src.

mi-estudio/
├── index.html
├── src/
│   ├── experiment.js        configuración y línea de tiempo
│   └── questionnaires.js    definición de cuestionarios y escalas
├── styles/
│   └── styles.css
├── README.md
└── AGENTS.md

Si reorganizás el proyecto así, index.html tiene que cargar cada archivo con su nueva ruta relativa, y questionnaires.js antes que experiment.js, porque el segundo usa lo que define el primero. Es un cambio que afecta varios archivos: pedí un plan antes de hacerlo, guardá una copia de respaldo y ejecutá el plan de pruebas completo después.
